# PIT-022 · OEM 解锁资格收紧：账号年限、实名、名额与冷却期成为隐藏前置

> 证据等级：**官方公告 + 公开报道 + 社区资料；本项目未实测**。适用于一加/ColorOS 及类似收紧解锁的 OEM。

## 1. 症状

```text
- 设备本身可解锁，但官方申请入口要求账号注册满 N 天、实名/人脸、连续登录、名额、冷却期；
- 资料齐全仍被拒，或审核通过后名额在 14 天内过期需重申请；
- 二手设备卖家声称"可解"，收货后发现版本/账号/名额不满足，解锁计划停摆。
影响范围：整条 B 路线（解锁→Root→迁移）全部阻塞。
```

## 2. 触发场景

| 项 | 内容 |
|---|---|
| 设备/ROM | 一加 ColorOS 16+ / 2025-10 后发布机型（政策分界）；老机型是否豁免需按机型核实 |
| 触发动作 | 申请官方深度测试 / 执行 `fastboot flashing unlock` |
| 频率 | 政策期内必现；老机型不一定 |

## 3. 根因

- 官方把解锁资格从"设备能力"改为"账号+名额+时间"的组合前置：账号注册满 60 天、实名与人脸认证、绑定手机号、本设备连续登录 7 天、同一实名 30 天冷却、一年 ≤4 台、名额上限、14 天有效期、7 个工作日审核（官方 2026-07-24 调整公告，公开报道 2026-07-24）。
- 政策只对**ColorOS 16+ / 升级到 ColorOS 17+ 的机型**明确生效；更老是"不受影响"，但**不代表老机型免流程**，仍需逐机型核实（待验证）。
- 二手市场无"资格"信息，卖家无法替买家满足账号条件。

## 4. 规避与修复

```text
规避（事前）：
1) 采购前查该机型现行政策与"是否需要深度测试"；把"账号可满足+名额可抢"纳入采购决策；
2) 不买"已秒解/来源不明/已熔断"的机器；要求卖家提供当前版本与解锁状态证据；
3) 收货后先只读核对版本/政策，再决定是否升级/解锁；账号条件（注册时长/实名/连续登录）先满足再申请。
修复（事后）：
1) 审核未过/名额过期→按官方规则重新申请，不找付费代解；
2) 机型政策不可满足→放弃该机或换政策允许的机型，不用漏洞通道；
3) 记录申请/审核/名额时间线，避免重复申请触发冷却。
```

## 5. 验证

```bash
# 只读：核对版本与解锁状态（不执行解锁）
adb shell getprop ro.build.fingerprint
adb shell getprop ro.build.version.security_patch
adb shell getprop ro.boot.flash.locked
adb shell getprop ro.boot.verifiedbootstate
```

人工核对：官方公告的机型适用范围与生效版本；账号注册/实名/连续登录天数；一年解锁台数；名额有效期与审核周期。

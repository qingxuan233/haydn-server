## 症状

- 脚本、文档、日志或仓库历史中出现明文口令、token、认证串或私钥；secret scan/review 告警。
- 凭据可能已随仓库、备份、聊天记录扩散；仅删除当前文件后，历史提交或备份副本仍然存在。
- 只读巡检脚本把认证信息直接写进命令行或日志，运行一次就产生新的泄露痕迹。
- 会话中贴过私钥/口令，随后又被复制进备份物料或文档。

## 触发场景

- 快速调试：把口令直接写进命令/脚本，或用原地内联认证参数的方式调用接口；
- 构建/部署脚本用“默认口令”回退，未走受控秘密存储；
- 日志打印请求头、命令行参数或异常上下文；
- 明文凭据文件随备份/仓库/网盘传播；调试会话中粘贴私钥；
- 没有 pre-commit/CI secret scan，靠人工记忆。

## 根因

- 缺少统一的秘密卫生流程：没有受控秘密存储、没有扫描门禁、没有日志脱敏规范。
- 便利优先于安全：口令写死最省事；脚本默认值让“能跑”掩盖了凭据管理问题。
- 认知误区：“删掉那一行就安全了”——git 历史、备份、日志、聊天记录都可能有副本。
- 凭据复用：一个口令用于多个服务/角色，泄露后影响面被放大。

## 规避与修复

1. 发现即视为**已泄露**：先轮换全部相关口令/token/密钥，再清理文件；顺序不能反。
2. 当前文件整改：改为环境变量/受控秘密文件（权限 600）/密钥管理服务；脚本禁止内置默认口令回退。
3. git 历史清理需谨慎：使用 filter-repo/BFG 等工具并协调所有 clone 强制更新；无法保证时按“仓库已泄露”处置，全部重签。
4. 日志脱敏：不打印认证头、命令行参数与含秘密的异常上下文；错误信息不回显秘密。
5. 备份与会话纪律：备份加密且不含明文凭据；不在聊天/文档/工单粘贴私钥或口令。
6. 加门禁：pre-commit/CI secret scan + 高危模式检索（password/token/Authorization/私钥头）。
7. 定期审计脚本、配置、文档与历史；发现即补 PIT/GRD，并复查同类位置。

## 验证

- secret scan 0 命中；抽查脚本无硬编码口令与默认口令回退。
- 轮换后旧凭据全部失效，新凭据只存在于受控存储；日志样例无秘密。
- git 历史清理完成且所有 clone 已更新，或已按“已泄露”完成全面重签。
- 门禁在测试提交上能拦截明文凭据。

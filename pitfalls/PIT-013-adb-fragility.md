## 症状

- 维护时 `adb devices` 显示 unauthorized、offline 或为空；重插线无效，授权弹窗不出现。
- 无线调试在重启后失效或配对丢失；IP 变化后连接串失效；多台设备/多工具导致连错设备或 adb server 被重启。
- 唯一维护通道中断，远程侧无法修复，只能到现场操作。
- 自动化脚本把“无设备/未授权”当成可继续状态，继续执行后续步骤产生假结果。

## 触发场景

- 无线调试长期开启、重启/OTA 后未重新配对；
- 关闭“USB 调试（安全设置）”或撤销授权、更换 PC/重装系统导致旧 key 失效；
- 家庭网络 DHCP 变化、设备离线、端口占用或多 adb 客户端竞争；
- 把 ADB 当运行时依赖，而不是一次性维护通道。

## 根因

- ADB 授权与 PC 端密钥绑定，状态机对重启、换 key、撤销授权敏感；无线调试依赖配对与端口，重启后通常需要重新开启。
- 设备端安全策略会限制授权范围（例如需要额外开启“USB 调试（安全设置）”），不同 ROM 表现不同。
- 维护通道没有第二条路径时就是单点故障；一旦失联，能做的操作只剩现场处理。
- 脚本缺少前置断言，把“不可用”当“空结果”继续跑，放大问题。

## 规避与修复

1. 维护窗口原则：ADB 仅在维护窗口开启，结束后关闭无线调试、恢复 USB 状态；不长期开启（同时降低攻击面）。
2. 准备并演练恢复清单：检查线缆/端口 → 确认授权弹窗“始终允许” → 重启 adb server → 重新授权/重新配对无线调试；每一步写清判定标准。
3. 保留第二通道：服务器 SSH/控制台/带外重启等至少一条不依赖 ADB 的路径；ADB 不作为运行时依赖。
4. 连接管理：显式指定设备序列号或地址，固定一台管理机运行 adb server，避免多设备/多工具混淆。
5. 脚本前置断言：无设备/未授权直接失败退出（非 0），并保留诊断输出；不得继续后续破坏性步骤。
6. 换机/升级后把 ADB 可用性列入验收项，记录维护开关状态与授权结果。
7. 若远程必须用无线调试，先确认其在一轮重启后仍可快速恢复，再依赖。

## 验证

- 模拟 unauthorized：按恢复清单能在可接受时间内恢复授权并 `adb devices` 显示 device。
- 重启后按维护流程恢复：无线调试重新开启/配对成功，或改用有线恢复。
- 无设备场景：脚本退出码非 0 且有明确提示，不产生后续副作用。
- 维护结束后无线调试已关闭，设备无额外暴露面。

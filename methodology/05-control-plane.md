# MTH-006 · AI 控制面（Track C）

> **一句话**：AI 控制面（如 DSH 这类对话式 Agent）是服务器的**解释层 + 受控运维层**，负责"看懂状态、给出诊断、在允许的护栏内做小步运维"；它**不是**运行时依赖，必须能整体故障而不影响数据采集、服务与桥。
>
> 核心原则：**只读优先 → 受控写 → 人工兜底**；所有变更可审计、可回滚；Agent 越权一律视为故障。

## 1. 定位与边界

```text
人类（浏览器/聊天入口）
   │  HTTPS + 认证 + 限流
   ▼
AI 控制面（LLM 决策/解释/诊断）
   │  策略文件（AGENTS：只读优先、Tier 表、红线）
   ▼
受控执行层（server-ops：固定子命令 + 白名单 + 确认 + 快照 + 审计）
   │
   ▼
服务层（supervisord 服务、nginx、备份、日志轮转）        ← 数据面：桥 → 聚合 API → Console
```

| 是 | 不是 |
|---|---|
| 自然语言查询/解释/诊断 | 服务器运行时依赖（控制面挂掉数据照常采集） |
| 通过受控 CLI 做小步运维 | 任意 shell / 任意命令执行 |
| 策略与审计的执行者 | 策略与审计的修改者（策略归仓库/人工） |
| 手机状态的解释方（经聚合 API） | 桥 token/证书持有方，也不是桥的直接调用方 |

**必须**：控制面与被控服务**故障隔离**——控制面故障不影响桥、聚合 API、Console、采集器；数据面故障也不得阻断控制面自身启动。

## 2. 只读面与受控写面

### 2.1 只读面（Tier1，优先、免确认）

- 服务状态/健康/版本；日志（白名单、行数受限）；备份列表/最近成功时间；审计查询；遥测来源/新鲜度/缺失字段；证书/凭据只读检查（不打印值）。
- 输出同时支持**人类摘要 + `--json` 机器可读**；控制面只能解析结构化字段，禁止解析人类摘要做决策。
- 只读命令必须**无副作用**：不触发重启、不写配置、不清理日志。

### 2.2 受控写面（Tier2）

允许的写操作必须**同时满足**：固定子命令 → 参数白名单 → 显式确认 → 变更前快照 → 变更后验证 → 写审计。

| 动作 | 约束 |
|---|---|
| 单服务重启/启停 | 仅白名单服务；不得一次批量；不得重启隔离性服务（见 §9） |
| 配置检查后重载 | 先校验配置语法，再重载；失败不得重载 |
| 立即备份 | 备份后校验完整性 |
| 日志轮转 | 只轮转白名单日志；不动审计文件 |
| 升级/回滚 | **Tier3**，不开放给控制面（人工）+ 蓝绿流程，见 §8 |

**拒绝路径必须明确**：缺确认 → 拒绝（用法错误码）；服务名不在白名单 → 拒绝；参数未知 → 拒绝；审计写入失败 → 拒绝执行。

## 3. Tier1/Tier2/Tier3 分层

| 层级 | 谁执行 | 确认要求 | 典型动作 | 失败处理 |
|---|---|---|---|---|
| **Tier1 只读** | Agent 自主 | 无需确认 | 状态/健康/日志/审计/遥测/备份列表 | 重试一次；仍失败则报告，不猜测 |
| **Tier2 受控写** | Agent + 人工确认 | `--confirm` + 计划说明 + 人工同意 | 单服务重启、配置检查/重载、备份、轮转 | 从快照回滚；失败即停，不得连环重试 |
| **Tier3 人工** | 仅人类（SSH + 双重确认） | 双重确认 + 备份 | 恢复、升级、删除数据、改系统配置 | 人工按回滚方案执行；Agent 只提供只读证据 |

**要求**：

- Tier2 操作前必须**先讲计划**（做什么、影响谁、回滚怎么做、预计时长），得到人工明确同意后才带确认执行。
- Tier2 每次执行都要生成配置快照（变更涉及的配置文件/目录），快照与操作绑定可追溯。
- Tier3 永不对 Agent 开放；Agent 发现任务属于 Tier3 时，**停止并交接给人类**，不得用 Tier2 拼接实现 Tier3 效果。
- 任何"为了省事而绕过分层"的行为视为红线违规（[GRD-005](../guardrails/GRD-005-tiered-ops-confirmation.md)、[GRD-012](../guardrails/GRD-012-agent-operating-rules.md)）。

## 4. Agent 策略文件（AGENTS）设计

策略文件分两层，职责不同，**不得混用**：

| 层 | 位置 | 面向 | 内容 |
|---|---|---|---|
| 仓库协议 | 仓库根 [AGENTS.md](../AGENTS.md) | 所有改仓库的 Agent | 分层/权威顺序、front matter、任务生命周期、DoD、禁止项 |
| 运行期策略 | 部署到 Agent 的工作目录（示例见 [scripts 操作策略](../scripts/server/AGENTS.md)） | 控制面 Agent（运行时） | 只读优先、Tier 表、Bridge 边界、敏感值禁止、故障降级 |

**运行期策略必须包含的段落**（按顺序）：

1. **读序与状态源**：先读当前状态/健康，再读任务相关文档；状态数字只有一个权威来源。
2. **只读优先**：先 `status`/`health`/日志/审计，再判断是否需要任何写操作。
3. **Tier 表**：允许命令、确认要求、快照/审计说明、回滚方式；列出白名单服务。
4. **边界**：不持桥 token、不直连桥、不控制宿主 App 生命周期、不能启动 Android App、不经代理绕过白名单。
5. **敏感值禁令**：token/口令/私钥/证书/备份口令不进聊天、日志、文档、公网页面。
6. **故障降级**：桥不可用 → 解释"回退采集"，提示人工检查宿主；控制面自身故障 → 自愈/人工旁路。
7. **报告与证据**：变更后必须验证并给出命令与结果；未实测不得标完成。
8. **升级路径**：策略本身是活文件，结构性变更同步 [MTH-017](17-expansion-and-cli-contract.md)（变更传播）与 [CHANGELOG](../CHANGELOG.md)。

**可校验建议**：策略条目带稳定编号（如 `OPS-01`），每条对应一个护栏 ID 与检查方式；机器可读部分（白名单/命令表）尽量放配置而非自然语言，避免"提示词漂移"。

## 5. 自愈与看门狗

**有界自愈模型**：

```text
正常 --连续N次探测失败--> 疑似 --重启1次--> 观察期 --仍失败且退避到期--> 重启2次
   │                                │                                      │
   └── 恢复                          └── 恢复即清零                        └── 超次数 --> 熔断 + 人工
```

| 参数 | 要求 |
|---|---|
| 检测频率 | 固定周期（如 30s 级）；探测必须轻量、无副作用 |
| 判定 | 连续 N 次失败才动作（防抖）；单次超时不算故障 |
| 重启 | 只重启目标服务，不重启整机、不批量重启 |
| 退避 | 指数/固定退避；失败次数越多间隔越长 |
| 上限 | 达到次数上限进入**熔断**：停止自动动作，输出告警供人工处理 |
| 清零 | 连续成功后清零计数并记录恢复事件 |
| 日志 | 每次判定、动作、结果、耗时都写日志/审计 |

**"不可自杀"原则**：

- 看门狗与目标服务**不得同生共死**：监控者不能由被监控者拉起或共用同一崩溃域（独立服务/独立进程）。
- Agent 不得重启"自己运行所依赖的服务"（例如控制面所在的运行时、鉴权入口、网络代理、审计写入通道），否则可能自锁死。
- 不得重启隔离性服务（网络/防火墙/代理/SSH/审计/策略源）；这些失败必须留给人工旁路。
- 不得通过"连环重启"掩盖问题；每次自动动作后必须有观察窗口，失败即熔断。
- 相关踩坑：[PIT-020 看门狗自愈级联](../pitfalls/PIT-020-watchdog-selfheal-cascade.md)、[PIT-014 配置重载自锁](../pitfalls/PIT-014-config-reload-lockout.md)。

## 6. 审计

**必记字段**（机器可读，一行一条 JSONL）：

| 字段 | 说明 |
|---|---|
| `ts` | UTC ISO8601，服务端时钟 |
| `actor` | 调用者身份（Agent/人类/脚本名；不含 token） |
| `tier` | `T1`/`T2` |
| `cmd` | 子命令名（白名单内） |
| `args` | 参数（**脱敏后**：不含凭据、不含 URL query token） |
| `target` | 目标服务/对象 |
| `snapshot` | 若产生快照，记录快照标识/目录名 |
| `result` | 成功/失败/拒绝 + 错误码 |
| `duration_ms` | 耗时 |
| `verify` | 变更后验证结果（健康/日志摘要） |

**要求**：

- 审计是**只追加**文件；Agent 不得删除/编辑/轮转审计日志（轮转归 Tier2 以外的受控脚本）。
- 审计查询本身是 Tier1；审计展示面只读。
- 脱敏规则：Authorization/Cookie/`token`/`password`/`secret`/`key` 类字段一律替换为占位符；不要把完整 URL 落审计（去除 query）。
- 保留期与容量：按磁盘水位设定；审计文件纳入备份范围。

## 7. 蓝绿升级与回滚

**适用**：控制面自身或关键前台服务的版本升级（改代码/依赖/运行时）；不适用于日常小配置变更（走 Tier2 快照回滚）。

```text
1) 备份      变更点配置 + 数据目录 + 版本锁定清单（含依赖 hash）
2) 候选实例  新版本装到独立目录；独立 profile/独立端口（值由部署配置，不写入文档）
3) 候选验证  仅内网/loopback 验证：进程、日志、鉴权入口、健康
4) 切换      两处必须同步：流量上游指向 + 登录/令牌绑定；只切一处会出现"登录与页面不一致"
5) 观察      10–30 分钟：错误日志、内存、健康、可用性
6) 结果     成功 → 旧版保留为回滚副本；失败 → 恢复备份配置 + 重载 + 验证
7) 清理      停用候选、删除临时配置、确认服务计数/端口恢复
```

**必须**：

- 切换前对**每一处**需要改的配置做带时间戳备份；回滚以"恢复这些备份 + 重载 + 验证"为最短路径。
- 候选实例使用独立 profile/独立数据目录，避免与线上争锁。
- 升级失败回滚时限目标 ≤10 分钟；回滚后必须重跑验收清单。
- 升级动作属 Tier3（人工批准 + 维护窗口），蓝绿只是**降低人工风险**的流程，不是授权 Agent 自动升级。

案例：[docs/23 蓝绿升级演练](../docs/30-dsh/23-DSH蓝绿升级演练.md)（历史演练报告 + 复用手册；§4 流程仍现行）。

## 8. 边界（必须逐条守住）

- **不持有桥 token / 证书私钥**；桥的凭据只属于服务器本地聚合进程。
- **不直连桥**：桥是服务器内部凭据面；控制面只能读聚合 API 与只读状态命令。
- **不控制宿主 App 生命周期**：启动/停止/重装 Bridge 属宿主维护动作，只能人工 + 维护通道。
- **不能启动 Android App**：Linux 容器内无 ADB 权限；禁止尝试、禁止建议用 ADB/run-as 代拉。
- **不绕过白名单/确认/审计**：不用 shell 拼接、不用配置改写来实现被禁命令。
- **不改策略与审计**：策略归仓库/人工维护；审计只读。
- **不新增公网入口**：任何外部暴露需用户明确批准并走安全评审（[MTH-007](06-security.md)）。
- **不自动执行 Tier3**：恢复/升级/删数据只能人工。
- **不把敏感值当解释材料**：回答"为什么卡"可以引用来源/新鲜度/错误，不得回显凭据。

## 9. 自锁死防护清单

| 危险动作 | 为什么危险 | 替代做法 |
|---|---|---|
| 重启网络/代理/防火墙 | 切断自己与人工旁路的连接 | 只读诊断；必要时人工现场/带外复位 |
| 重启鉴权入口/登录服务 | 期间无法登录，无法回滚 | 只读检查 + 人工批准窗口 |
| 重启审计写入服务 | 变更失去留痕 | 先修审计通道（只读查因），再谈变更 |
| Agent 重启自己所在运行时 | 会话中断、状态不一致 | 交给独立看门狗/人工 |
| 一次性批量重启多个服务 | 叠加故障不可归因 | 单服务、逐个、每次验证 |
| 关闭或绕过确认机制 | 不可审计、不可回滚 | 禁止；视为红线违规 |
| 修改策略文件使自己获得更大权限 | 提权 | 策略变更需人工 + PR 评审 |

## 10. 最小可用落地顺序

| 顺序 | 内容 | 判定 |
|---|---|---|
| 1 | 只读执行层：状态/健康/日志/备份/审计 + 机器可读 JSON + 审计落盘 | 所有只读命令可用且无副作用；审计可查 |
| 2 | 策略文件（AGENTS）+ 控制面接入只读；看门狗（独立服务、连续失败才重启、熔断） | 控制面故障不影响数据面；看门狗自愈演练通过 |
| 3 | Tier2 受控写：确认 + 快照 + 审计 + 变更后验证；白名单服务 | 拒绝路径（无确认/非法服务）均可复现 |
| 4 | 蓝绿升级演练 + Console/审计展示 | 切换与回滚都演练过；审计可视化只读 |
| 5 | 可选：外部告警、异地备份、MFA、私网通道 | **需用户明确批准**，默认不做 |

## 11. 验收清单

- [ ] 控制面故障（停服务）时：聚合 API、采集、桥、Console 均正常；恢复后自动继续。
- [ ] 只读命令全部可用且输出结构化；无写副作用。
- [ ] Tier2 缺确认 → 拒绝；非法服务 → 拒绝；错误参数 → 拒绝；三者退出码可区分。
- [ ] Tier2 成功路径产生快照 + 审计 + 变更后验证三项齐全。
- [ ] 审计文件只追加、字段齐全、敏感值脱敏；Agent 无删除/编辑能力。
- [ ] 看门狗：连续失败触发重启；成功清零；超限熔断；不重启隔离性服务。
- [ ] 蓝绿切换两处同步；回滚 ≤ 目标时限（默认 ≤10 分钟）且验证通过。
- [ ] 桥 token 不在控制面可读范围；控制面无任何直连桥的配置。
- [ ] 策略文件与实际允许命令一致（无"文档允许、工具不支持"或反之）。

## 12. 常见失败与 fallback

| 现象 | 原因 | 处理 |
|---|---|---|
| 控制面无法登录 | 入口/鉴权配置变更未同步 | 人工旁路（SSH/Console）；按备份回滚登录配置 |
| 控制面重启后令牌变化 | 会话/令牌每次重启重生成 | 走统一登录入口重新登录；不硬编码令牌 |
| 看门狗反复重启同一服务 | 根因未修（配置/磁盘/依赖） | 熔断并人工定位根因；禁止调大重启次数掩盖 |
| Tier2 后服务未恢复 | 快照未覆盖全部变更面 | 立即从快照回滚 + 人工核对；补变更面清单 |
| 审计写入失败 | 磁盘满/权限/轮转冲突 | 拒绝执行写操作；先修审计与磁盘 |
| 升级后登录/页面不一致 | 只切了流量上游，未切登录/令牌绑定 | 两处同步切换或整体回滚 |

# MTH-013 · 项目推进与交付治理

> **一句话**：本仓库擅长"改造一台设备并验证它"，但**代码/脚本改完不等于项目交付**——需求会漂移、没人对用户结果负责、能跑却无法在目标环境部署/观测/恢复、升级与弃用引发兼容事故、数据与许可问题到发布才暴露。本文把这些风险转成**按风险缩放的阶段门与责任约定**，落地参考 Agent-Harness v1.3 的 03 册裁剪版。
> **权威边界**：技术阶段与路线门禁由 [MTH-003](02-roadmap.md) 定义，验收证据由 [MTH-008](07-validation.md) 定义，红线由 [guardrails/](../guardrails/README.md) 定义；本文只补**项目推进、用户验收、发布/割接与长期维护**。本文与参考规范中**未在 haydn 实测**的机制一律标"待落地/未实测"，不得表述为已验收。

## 1. 结论先行

1. **风险分级先于流程**：L/M/H 决定最小流程；不确定影响时按较高一档，不得因"Agent 能自动完成"降级。
2. **每个关键决策有一位明确 Owner**：用户是**唯一最终验收人**，Agent（含子 Agent）不可替代；"待定/团队名/Agent 名"不算负责人。
3. **M/H 任务先有需求基线卡**（目标/非目标/验收/风险/影响面），验收条件批准后即为基线，变更必须走变更单，不得静默改卡。
4. **交付门 G0–G7 与 MTH-003 的 P0–P6、路线门禁 G-A/G-B0/G-L* 并行**：两边都要过，交付门不替代技术门，也不降低红线。
5. **发布/割接前必须有可重复部署、可观测信号、runbook、Go/No-Go 卡**；没有演练过的回滚视为没有回滚（[GRD-004](../guardrails/GRD-004-backup-before-change.md)）。
6. **兼容、弃用、数据隐私、依赖许可是发布门的一部分**；未实测项标"待落地"，不得写"已通过"。

## 2. 风险分级：流程按影响缩放

立项或任务开始时定级；任何人（含 Agent）可提高等级，降低须责任人说明依据。

| 档 | 本仓库例子 | 最小流程 |
|---|---|---|
| **L（低）** | 文档修订与导航（MTH/PIT/GRD 正文）、术语补充、局部脚本小修、模板文案、注释/链接修正；不改变接口/数据/权限/部署 | 任务卡（目标+验收）→实施→验证→汇报 |
| **M（中）** | 新增工具子命令、OEM profile 适配、CI 质量门、桥参考实现、模板/契约字段新增、常规版本发布、跨模块文档重构 | 需求基线卡（目标/范围/非目标/验收/Owner）→影响评估→评审→测试→变更记录 |
| **H（高）** | 解锁/Root/刷机/固件变更、数据迁移、生产割接（服务器栈迁移/换机）、隐私数据采集与备份处理、不可逆操作、重大兼容性变化、顶层目录/ID 前缀/schema 主版本变更 | 完整提案+风险分析+明确批准者→测试/用户验收→运行就绪评审→回滚/恢复证明→发布签核与观察计划 |

**默认规则**：不确定档位暂按较高一档；H 级任务的批准者是用户（或用户书面指定的责任人），Agent 只能整理证据与给出推荐。

## 3. 角色与责任（每个任务/项目必须可答）

| 角色 | 责任 | 记录位置 |
|---|---|---|
| **DRI / 结果负责人** | 对目标、范围、验收和是否交付负责；不是"写代码的人"默认担任 | 需求基线卡（REQ） |
| **技术 Owner** | 架构、接口、数据迁移、技术风险与长期维护 | 相关 MTH/README 或组件目录 |
| **用户验收人** | 确认代表性任务与业务结果是否满足；**用户本人**，Agent 不可替代 | 需求卡 + 验收卡（ACP） |
| **发布/运行 Owner** | 发布窗口、运行监控、故障升级、回滚决策 | runbook（RUN） |
| **安全/隐私/许可顾问（按需）** | 高风险数据、权限、外部依赖、许可审查 | 风险登记/审批记录 |

- **必须**：每个关键决策有且仅有一位决策 Owner；协作者/评审者可多人，但争议由 Owner 裁决；安全/许可红线不能由项目 Owner 豁免。
- **必须**：Owner 不可用时记录代理人与升级对象；不得只写团队名、Agent 名或"待定"。
- **应当**：路径责任可用 `CODEOWNERS` 等等价机制，但工具规则不等于完整业务责任矩阵。

## 4. 需求基线卡与变更控制

### 4.1 轻量需求基线（M/H 任务实现前）

用 [request-card 模板](../toolkit/templates/request-card.md)（示例 ID 占位），逐项不得留空：

| 字段 | 必须回答 |
|---|---|
| ID / 状态 / DRI / 验收人 / 目标版本 | 谁负责结果、谁验收、计划进哪版 |
| 背景与问题 | 谁遇到什么问题，现有证据是什么（链接 PIT/案例/命令输出） |
| 目标（Goals） | 本次要达成的**可观察**结果 |
| 非目标（Non-goals） | 明确本次不做什么，防止范围漂移 |
| 用户/系统场景 | 输入、动作、成功结果、失败/边界场景 |
| 验收条件 | 可执行或可观察的通过/不通过判据（含失败、空数据、权限不足、错误恢复） |
| 依赖与约束 | 接口、数据、版本、外部服务（须用户同意，[GRD-009](../guardrails/GRD-009-external-services-consent.md)）、时间 |
| 风险与备选 | 主要风险、最小可行方案、放弃/延期条件 |
| 影响面 | API / profile schema / 遥测字段 / 权限 / 隐私 / 部署 / 运维 / 文档 |

> 参考 Kubernetes KEP 的可迁移经验是 Summary/Goals/Non-Goals/Risks/测试计划；小项目只取关键字段，不照搬完整 KEP 模板（未实测项：本仓库尚未用该模板推进过完整 M/H 项目）。

### 4.2 变更控制（基线之后）

- **必须**：验收条件批准后即为基线；新增需求、移除目标、改验收、改发布日期或兼容承诺**都算变更**，记录变更单：内容、原因/新证据、范围/工期/接口/数据/安全/验收影响、建议决策（接受/拒绝/延期）、决策人+日期。
- **必须**：DRI 批准后同步更新需求卡、任务拆分、测试与发布说明；未获批前按原基线执行或暂停受影响部分。
- **必须**：紧急安全/数据丢失处理可走快速路径，但事后必须记录复盘、影响对象、补偿措施与无法走常规审批的原因。
- **必须**：重大目标变更重新确认 Continue/Pivot/Stop（§11），不把沉没成本当继续理由。
- **拆分**：Agent 可整理证据、列备选、起草提案；产品取舍、预算、隐私风险接受、发布 Go/No-Go 的最终决定必须由指定人作出并留痕（见 [MTH-014](13-agent-sop.md) §10）。

## 5. 从需求到交付的阶段门 G0–G7

大项目按门推进；L 级可合并阶段，H 级不得跳过签核证据。

| 阶段门 | 继续推进前必须回答 | 不通过时 |
|---|---|---|
| **G0 立项/发现** | 问题是否真实？目标用户是谁？现有证据/现状是什么？不做会怎样？ | 暂停实现，补发现工作或拒绝立项 |
| **G1 范围/基线** | Goals、Non-goals、验收、DRI、依赖、风险是否明确？ | 澄清后再排期；不得让 Agent 自行补需求 |
| **G2 方案/可行性** | 方案与替代项、接口/数据影响、安全隐私、运维成本是否评估？ | 记录未决项；高风险项需 Owner 批准后进入实现 |
| **G3 实现/验证** | 测试、迁移、文档与反例是否按计划完成？ | 不得标完成；返工或记录批准的豁免与风险 |
| **G4 用户/业务验收** | 代表性任务能否完成？用户/业务验收人是否确认？指标如何测？ | 修复/缩小范围/延期；技术测试通过不替代用户验收 |
| **G5 发布就绪** | 目标环境、部署、配置、监控、告警、支持、回滚、依赖/许可是否就绪？ | No-Go；发布 Owner 明确延期或签署有时限的风险接受 |
| **G6 发布与观察** | 实际版本/制品/配置/固件是什么？观察窗口、告警阈值、回滚条件、值班人是谁？ | 触发止损/回滚/事件响应，形成事故记录 |
| **G7 复盘/生命周期** | 目标是否达成？未完成债务/兼容承诺由谁何时处理？ | 更新路线图、需求卡、知识库；必要时 Stop/退役 |

- **证据纪律**：每门记 `PASS / FAIL / WAIVED`；**WAIVED 必须有批准人、理由、残余风险、补偿控制与到期日**；Agent 不得自行豁免；没有记录的"口头通过"视为未通过。
- **与 MTH-003 的关系**：P0–P6 是**设备改造技术阶段**、G-A/G-B0/G-L* 是**阶段/路线门禁**；G0–G7 是**项目/交付治理门**，两者并行。例：一次解锁同时受 MTH-003 P4 决策门、[MTH-012](11-root-lab.md) G-L0..G-L6 与本文 H 级 G2/G5/G6 约束；过技术门不等于过交付门，交付门也不替代技术门。
- **未实测声明**：G0–G7 在本仓库尚属"已立规范、未在真实项目全流程演练"；首个真实 H 级割接的 Go/No-Go 记录进 backlog。

## 6. 用户验收（G4）

### 6.1 何时必须用户验证

M/H 级且面向用户/业务结果的改动（换机迁移、割接、桥/控制面新能力、验收口径变化）必须从**真实任务**出发；实现者自定"看起来可用"不算验收。

### 6.2 最小验收卡

| 字段 | 内容 |
|---|---|
| 用户/角色与代表性任务 | 如"重启后远程登录与健康检查可用""soak 观察期内服务不中断""桥不可用时回退并标注来源" |
| 当前痛点/基线证据 | 改造前状态、失败频率、命令或日志证据 |
| 目标结果与测量方法 | 可观察结果 + 采集命令/仪表口径 |
| 验收参与者/签核人 | 用户本人或用户书面指定的业务验收人 |
| 成功判据 | 含**失败、空数据、权限不足、错误恢复**路径；null 不得被当作 0（见 [MTH-005](04-telemetry-bridge.md)） |
| 反馈渠道与观察期 | 谁收集、观察多久、何时复核 |
| 未覆盖用户群与已知限制 | 不写"所有用户都能用"等无证据表述 |

- **必须**：至少一个关键 happy path 与一个失败/恢复路径由用户/验收人实际走通并记录观察结果，不保留可识别个人数据。
- **必须**：高影响功能给可衡量指标（任务完成率、错误率、恢复耗时、支持请求量），标清事件口径、数据来源与观察窗口。
- **必须**：发布后由 DRI 在约定观察期复核目标；未达成则改进/回滚/扩大验证/停止该功能。

## 7. 发布与割接就绪（G5）

"本地构建/命令通过"≠"可发布"。生产/外部可见的 M/H 变更发布前至少完成：

### 7.1 可重复部署

- 记录目标环境（Android 大版本/ABI、Termux/rootfs 版本、依赖服务）与支持矩阵；配置项有说明、默认值与安全存储方式（凭据不写文档，[GRD-006](../guardrails/GRD-006-secret-hygiene.md)）。
- 部署步骤由**非作者**按文档在干净环境或等价 staging 演练，记录命令、版本、结果与人工步骤；有健康检查/启动检查与最小 smoke test；明确哪些环境无法自动验证。
- 数据迁移/回滚/恢复按 [MTH-008](07-validation.md) §6 演练并记录；向前/向后兼容按 §8 验证。

### 7.2 可观测与可诊断

- 说明关键流程健康信号（SLI）与阈值（SLO 或等价目标）；无法承诺精确 SLO 时先定义检测信号与人工巡检节奏。
- 明确关键错误、依赖不可用、队列积压、任务失败如何被发现；告警可行动、谁接、何时升级。
- **日志/指标/追踪字段名属于消费者契约**：改名/删除/改语义遵循 §8；禁止遥测含凭据/个人敏感数据（[GRD-006](../guardrails/GRD-006-secret-hygiene.md)、[GRD-011](../guardrails/GRD-011-privacy-inventory.md)）。

### 7.3 runbook 与事件响应

- 生产服务必须有短而可操作的 runbook：检测信号 → 初步判定 → 止损 → 回滚/恢复 → 升级联系人 → 复盘记录位置；指定主责与替补；无持续值班能力时写明支持时段与响应预期，不能假装 24×7。
- 事故处理：先保护人/数据/服务并控制影响；记录时间线、影响范围、已采取动作与不确定项；禁止为"修得快"销毁证据；恢复后复核数据完整性并用可复用教训沉淀 PIT。

### 7.4 Go / No-Go 发布卡

| 字段 | 内容 |
|---|---|
| DRI / 发布 Owner / 时间窗口 / 目标环境 | 谁签、谁盯、何时、在哪 |
| 版本、源提交、制品/固件校验值 | 可追溯（对齐 §10 与 [GRD-014](../guardrails/GRD-014-firmware-freeze-ota.md)） |
| 需求基线与已知不做项 | 链接 REQ/需求卡 |
| 构建/测试/安全/许可/迁移结果 | 命令+退出码+证据位置；未执行项列明 |
| 部署与 smoke test 结果 | 非作者复现 |
| 监控、告警阈值、观察窗口、响应人 | 见 §7.2 |
| 回滚触发条件、步骤、恢复验证 | 见 [GRD-004](../guardrails/GRD-004-backup-before-change.md) |
| 未解决风险及批准豁免 | 批准人 + 到期日 |
| 决策：GO / NO-GO / 有条件 GO | 签核人 + 日期 |

> 模板见 [runbook 模板](../toolkit/templates/runbook.md)；本仓库尚未有真实 Go/No-Go 签核记录（待落地）。

## 8. 兼容、升级与弃用

### 8.1 兼容对象清单（本仓库特有）

| 生产者 | 消费者 | 兼容承诺 |
|---|---|---|
| Android 宿主大版本 / OEM ROM | Termux、Bridge APK、Termux:Boot | 升级前核对 FGS 类型、自启/省电策略（profile 记录） |
| Bridge APK 版本 | 服务端合并/降级逻辑、控制面 | 旧 APK 连新服务端、新 APK 连旧服务端都要声明支持矩阵 |
| profile schema / 遥测字段名与语义 | assess/plan、控制面、仪表盘、审计与告警 | 字段即契约：新增须可选；改名/删除走 §8.2 |
| rootfs/依赖版本 | 服务器栈与备份脚本 | 仅支持同步升级时必须声明停机与迁移要求 |
| 固件/OTA 版本 | 解锁/Root 前提、救援包 | 冻结与受控升级见 [GRD-014](../guardrails/GRD-014-firmware-freeze-ota.md) |

矩阵写法：`生产者版本 | 消费者版本 | 支持？ | 升级先后/限制 | 测试证据`；**没有测试证据的"支持"按不支持**。

### 8.2 破坏性变更的渐进路径

- **必须**：先新增兼容入口/字段/格式（可双读/双写），迁移消费者后切默认，公告弃用窗口后才移除旧入口；数据迁移用 **expand → migrate/backfill → switch → contract**，删除旧 schema 前验证所有活跃消费者已迁移。
- **必须**：弃用条目写清替代方案、开始版本/日期、最早移除版本/日期、影响对象、迁移步骤、检查方式与负责人；只有替代项稳定可用后才启动弃用；安全/数据丢失风险可缩短周期但须说明理由与回退风险。
- **禁止**：把"只支持同步升级"藏起来不写；没有版本兼容承诺的系统必须显式声明停机/迁移要求。

### 8.3 生命周期状态

- 本仓库统一：`draft（Experimental/开发中）→ current（Stable）→ deprecated（Deprecated）→ archived（Removed）`；对外契约（profile schema、遥测字段、CLI 输出 schema）必须声明所处状态。
- 稳定契约需兼容承诺；deprecated 必须给出窗口与替代；archived/移除必须版本升级、迁移指南与变更记录（见 [MTH-011](10-document-lifecycle.md) §2.4 ADR 纪律）。

## 9. 数据治理与隐私

隐私治理处理**个人数据与敏感业务数据的全生命周期**，不只是防 token 泄漏；对齐 [GRD-011](../guardrails/GRD-011-privacy-inventory.md)。

### 9.1 本仓库数据地图

| 数据 | 位置/形态 | 最小化要求 | 保留与删除 |
|---|---|---|---|
| 设备档案（型号/版本/网络能力/序列号风险） | `profiles/`（gitignored） | 脱敏后仅放 `cases/`；序列号不入库 | 换机/任务完成后按用户要求删除 |
| 采集快照/会话产物 | `inventory/`、临时目录（gitignored） | 只存任务必要字段 | 默认短期保留（建议 ≤30 天）后清理 |
| 备份/密钥材料 | `backup/`、`.env`（gitignored） | 加密存储、最小权限 | 按 RPO/保留策略；删除须验证含缓存/日志 |
| soak/验收证据 | 验收报告/JSON（脱敏） | 地址/端口/凭据/个人数据一律脱敏 | 随验收归档；不保留可识别个人数据 |
| 桥遥测（宿主状态） | 本机 HTTPS、日志/快照 | 只读、最小字段、loopback | 按控制面保留策略；禁止外发 |

### 9.2 必须回答的六问

| 维度 | 必须回答 |
|---|---|
| 数据与来源 | 收集/生成哪些数据？来自哪里？是否含真实用户/生产数据？ |
| 目的与依据 | 为何需要？用于什么？授权/同意由项目责任人核实（本文不是法律意见） |
| 最小化与访问 | 能否少收/脱敏/聚合？谁读写/导出？如何审计？ |
| 共享与处理者 | 是否发送给 Agent 服务、模型供应方、分析平台或第三方？数据是否离开受控边界？ |
| 保留与删除 | 保留期限/触发条件？如何验证删除（含缓存/日志/备份）？ |
| 事件处置 | 误发/越权/泄漏如何检测、止损、通知 Owner/隐私负责人？ |

- **禁止**：把生产数据或个人信息输入未获批准的模型、网页、工单、测试 fixture 或协作渠道；数据是否可外发由用户/数据负责人依适用政策裁定。
- **必须**：验收/研究记录只保存必要、脱敏、限权内容；研究数据默认不保留可识别个人身份信息。
- **必须**：删除请求与保留义务冲突、跨境/监管义务、同意依据等法律问题升级给有权限的人处理。
- **未实测声明**：本仓库尚未演练"删除后验证（含备份）"流程，标待落地；不以"符合隐私框架"自证合规。

## 10. 依赖、许可与制品来源

对齐 [GRD-010](../guardrails/GRD-010-license-compliance.md) 与 [GRD-014](../guardrails/GRD-014-firmware-freeze-ota.md)。

- **零依赖优先**：`toolkit/` 必须保持零第三方运行时依赖（当前已满足，见 [toolkit/README.md](../toolkit/README.md)）；新增依赖须评估许可、体积、可复现与安全影响（M 级流程）。
- **Android Bridge 依赖**：记录 SDK/库版本、许可证与更新策略；构建输入可追踪（版本/哈希），自动更新须配合测试与评审，不能只锁不更新。
- **固件与工具来源**：解锁/Root/救援涉及的固件包与刷机工具必须记录来源、版本与 SHA-256 校验（见 [PIT-024](../pitfalls/PIT-024-flash-tool-supply-chain.md)）；来源无法确认的二进制不得宣称为本项目官方推荐制品。
- **许可证**：登记直接依赖与分发许可；出现限制/冲突时暂停分发并由负责人审查；机器可读 SPDX 表达不能替代法务审查。
- **漏洞**：扫描依赖与构建镜像；阻断阈值按可利用性/暴露面/数据影响定义，例外必须写 Owner/理由/期限，不得永久无理由豁免。
- **制品来源（SBOM/provenance）渐进**：阶段一"记录源提交+构建步骤+制品哈希"→阶段二生成 SBOM（SPDX/CycloneDX）→阶段三构建 provenance/签名/消费者验证。**本仓库目前只做到阶段一的文本记录，SBOM 与 provenance 未落地**（标待落地，SBOM 术语见 [MTH-010](09-glossary.md)）。
- **例外**：不能生成 SBOM/扫描/签名时，说明技术原因、替代控制、风险 Owner 与复查日期；不得虚报"扫描通过"。

## 11. 项目健康度与 Continue / Pivot / Stop

每个里程碑由 DRI 回答：

1. 目标用户/业务结果是否有**证据**表明正在改善？
2. 未完成风险是否仍可接受？维护/运行/合规成本是否超过预期价值？
3. 关键依赖/Owner 是否仍可用？是否有受阻路径与替代方案？
4. 继续（Continue）、调整范围/方案（Pivot），还是停止（Stop）？

- **Stop/Pivot 时必须写清**：未交付项、数据/用户影响、未偿技术债、归档与维护责任、已承诺的兼容窗口；停止项目不是删除历史，也不是把维护责任留给无人认领的代码。
- 决策留痕：H 级 Stop/Pivot 走 ADR（见 [adr/README.md](../adr/README.md)）；L/M 级记入需求卡与变更记录。

## 13. 反例与自检

| 反例 | 为什么错 | 正确做法 |
|---|---|---|
| "功能做完＝交付完成" | 没有部署/观测/回滚/用户验收，生产必翻车 | 按 G3→G4→G5→G6 逐门留证 |
| 把 Agent 自测当用户验收 | Agent 不是验收人，技术测试不替代业务结果 | 用户/指定验收人实际走代表性任务 |
| 静默改验收条件/范围 | 基线漂移，返工与"移动的终点" | 变更单 + 决策人 + 重确认 Continue/Pivot |
| 无回滚演练 | 失败时无法恢复，[GRD-004](../guardrails/GRD-004-backup-before-change.md) 违规 | 恢复未演练视同无回滚 |
| 遥测/日志输出凭据或个人信息 | 越权暴露、违规且不可撤回 | 脱敏 + 最小化 + 访问控制 |
| 只说"支持旧版本"却无证据 | 兼容事故在发布后才暴露 | 矩阵 + 测试证据，否则声明不支持 |

**交付前自检**（逐项勾选）：

- [ ] 风险档已定（L/M/H），按档执行了最小流程，未因"Agent 能自动做"降级
- [ ] M/H 任务有需求基线卡；验收条件、非目标与影响面明确；变更走了变更单
- [ ] 当前阶段门记录为 PASS/FAIL/WAIVED；WAIVED 有批准人+到期日；未把口头通过当 PASS
- [ ] 用户/验收人实际走通代表性任务与失败/恢复路径，指标口径与观察窗口已写清
- [ ] 发布/割接：非作者按文档演练、可观测信号、runbook、回滚验证、Go/No-Go 卡齐全
- [ ] 兼容矩阵覆盖 Android 版本/Bridge APK/profile schema/遥测字段；弃用有替代与窗口
- [ ] 数据在 `profiles/ inventory/ backup/` 的采集/保留/删除/外发有明确边界，未把生产数据放进 fixture
- [ ] 依赖清单/许可证/固件哈希可追溯；无来源制品未宣称为官方构建
- [ ] 健康度问题（Continue/Pivot/Stop）有 Owner 与留痕；未完成项进 backlog
- [ ] 本文未实测的机制在报告中标注"待落地/未实测"，未写成已验收

# MTH-001 · 方法论边界与原则

> **结论先行**：本方法论把**一台闲置 Android 手机**改造成**低功耗、可远程维护、可观测的家用 Linux 服务器**。
> 默认路线是**无 Root 的 Termux + proot**（A 路线）；默认安全边界是**不 Root、不刷机、不解锁 Bootloader、不接未授权外部服务**；所有变更必须**可回退、有证据**。
> 本页定义"做什么、不做什么、按什么原则做"，是所有后续文档（评估、路线图、服务器栈、桥、控制面、安全、验收）的上位约束。

---

## 1. 目标用户与场景

| 用户类型 | 典型场景 | "成功的样子" | 何时不该用本方法论 |
|---|---|---|---|
| 个人自托管爱好者 | 把淘汰手机变成文件同步/备份/轻量 Web/下载/定时任务节点 | 断电重启后无人值守自动恢复；手机温度与功耗可接受；可远程维护 | 需要低时延高并发、需要 ECC/企业级可靠性的生产业务 |
| 小团队内网服务 | 内网监控聚合、开发环境、CI 辅助节点、个人网盘 | 局域网内可控访问；数据每日备份；故障可在十分钟级恢复 | 需要对外提供公众服务、合规审计或 SLA 承诺 |
| 研究/教学 | 验证 Android 宿主限制、宿主机遥测、无 Root Linux 能力 | 有可复现步骤、结构化设备档案、明确的"不可得清单" | 需要系统级改机、刷机测评、破解类内容 |
| 后续 Agent 维护者 | 换机迁移、方法论修订、工具扩展 | 读 `AGENTS.md` + 机器索引即可接手；校验命令全绿 | 想跳过门禁直接批量改文件 |

**典型可用服务**（设备无关、按需裁剪）：SSH 远程登录、反向代理与 TLS 入口、文件同步/备份、轻量 Web/面板、定时任务、监控聚合、内网 DNS/工具页、自托管代码仓库。**不保证**数据库重负载、容器编排、GPU 加速、实时音视频类负载。

## 2. 适用前提（推荐条件）

| 前提 | 建议值 / 判定 | 检查方式 | 不满足时的后果与退路 |
|---|---|---|---|
| Android 版本 | **建议 Android 11+**；遥测桥的 `specialUse` FGS **需 Android 14+** | 设备档案 `identity.android_release` / `sdk_int`（见 [MTH-002](01-assessment.md)） | 低于 11：Termux/自启问题多，降级为实验；14 以下无桥 → 仅 A 路线 + Termux 采集 |
| 内存 | 建议 ≥4GB，8GB 更稳 | `hardware.ram_mb` | 过小：服务需精简到 1–2 个，避免被 LMK 杀 |
| 存储 | 建议可用 ≥32GB | `storage.data_free_gb` | 不足：不装大服务，备份与日志必须外置 |
| 网络 | 有可用 WiFi；**地址可动态变化**（不要求 DHCP 保留/静态 IP/路由器管理权限）；能通过**发现机制**（页面显示/扫码/mDNS/广播发现之一）或经用户批准的受控隧道访问 | 现场网络核对 + `constraints`/`assumptions` | 无固定地址并不阻塞 A 路线：用动态地址 + 发现机制；若连稳定发现都不可得，标记"仅临时可用"并写限制 |
| Root 状态 | **无 Root 即可完成默认路线（A）** | `root.root_available_current` | 有 Root：仍默认走 A，只在门禁通过后选 B |
| Bootloader | **默认保持锁定** | `boot.bootloader_unlocked` | 已解锁但不想承担代价：仍按 A 路线 |
| 系统管理预期 | 接受"假 root、无 systemd、无容器（若内核缺 NS）" | `kernel.config` 字段 | 不接受：只能评估 B/C 路线（高风险、需授权） |
| 无人值守自启 | 无锁屏凭据（FBE 下 BOOT_COMPLETED 可能晚于解锁）或可接受人工启动 | 现场确认锁屏策略 | 有锁屏凭据：自启可能延迟/失败，必须在验收中如实标注 |
| 供电与散热 | 长期插电可接受；能开限充/散热措施 | 设备档案 `hardware` + 现场 | 无法限充：电池长期满电有鼓包风险，需写进限制清单 |
| 变更与恢复资源 | 有备份空间与回滚时间预算 | `constraints` | 无备份空间：先解决备份，不允许做破坏性变更 |

> **默认假设**（探测无法确认时使用，并写入 `unknowns`）：硬件的断网/重启恢复能力未经验证；OEM 不会因为系统大版本升级改变后台策略；用户接受"轻量应用服务器"而非"标准 Linux 服务器"。
> 以上均为**假设**，不是承诺；真机验证后才升级为事实（`source: measured`）。

## 3. 三轨架构

```text
┌─────────────────────────────────────────────┐
│ Track A  服务器栈（宿主 Linux 用户态内）      │
│ 反向代理 / 服务守护 / 备份 / 审计 / 状态聚合  │
└───────────────┬─────────────────────────────┘
                │ Track C  集成与控制面
                │  · 只读状态 API 与合并
                │  · 只读查询 / 受控运维（Tier1/2）
                │  · 审计与回滚入口
┌───────────────▼─────────────────────────────┐
│ Track B  宿主遥测桥（Android 伴生只读 App）   │
│ Boot 广播 → 前台服务 → 本机 HTTPS 只读快照    │
└─────────────────────────────────────────────┘
```

| 轨道 | 职责 | 输入 | 输出 | 失败时 | 明确不做 |
|---|---|---|---|---|---|
| **A 服务器栈** | 跑 Linux 服务、聚合状态、存数据、备份、审计 | 宿主提供的用户态 Linux 环境；C 转发来的宿主状态 | 服务端口（仅局域网/受控入口）、状态 API、备份包 | 拓扑仍允许 B 单独运行；C 降级 | 不直接读 Android 硬件 API；不持有桥密钥 |
| **B 宿主遥测桥** | 采集 App 可访问的宿主状态并只读暴露 | Android 系统 API/权限 | 本机 HTTPS 只读快照 + 能力清单 | A 回退到 Termux 采集并标注来源 | 不跑 Linux 服务、不做特权操作、不开写端点 |
| **C 集成与控制面** | 读取/合并状态、展示、受控运维、审计 | A 的状态 API、B 的只读快照、工具链 | 面板/查询/操作记录 | A、B 不受影响；仅控制功能不可用 | 不持 Bridge token、不直连桥、不控制桥生命周期 |

**接口约束（必须）**

1. 桥**仅 loopback**、只读、TLS + token + 证书 pin；任何写/exec/任意 URL 端点都是违规设计。
2. 控制面只走服务器 API 与受控运维入口；**不持有桥 token、不尝试启动/停止宿主 App**。
3. 桥不可用（崩溃/被杀/权限失效/证书失效）时，服务器**回退**到 Termux 采集并显式标注数据来源与新鲜度；缺失字段一律 `null`，不得伪造为 0。
4. 三轨**各自自启、各自自愈**：任一轨故障不得阻断其余两轨（见 [MTH-004](03-server-stack.md)、[MTH-005](04-telemetry-bridge.md)、[MTH-006](05-control-plane.md)）。

## 4. 十条设计原则（必须）

| # | 原则 | 一句话含义 | 为什么重要 | 违反信号 | 落地要求 |
|---|---|---|---|---|---|
| 1 | **单一聚合** | 服务器是唯一的状态聚合/存储/展示方；桥只提供原始宿主状态 | 避免多个真相源导致状态打架、面板不可信 | 面板/桥/控制面各自缓存并各自解释数据 | 状态 API 合并 + 来源字段 + 新鲜度字段 |
| 2 | **故障隔离** | 桥、控制面、ADB、任一服务挂掉，不阻断其余组件 | 手机资源有限，级联故障会整机失联 | 控制面挂导致采集停；桥挂导致服务器不可用 | 独立自启链 + 看门狗 + 回退路径 |
| 3 | **最小权限** | 只授予完成目标所需的最低权限；凭据只在最小范围可用 | 手机是个人设备，越权即隐私风险 | 控制面拿到桥 token；桥监听非 loopback | token 文件最小可见、桥 GET-only、Tier 分级 |
| 4 | **可回退** | 每个变更都有快照/备份与明确回滚步骤，且演练过一次 | 无回滚的"优化"等于赌博；手机失联后现场成本极高 | 只有备份没有回滚步骤；回滚路径从未验证 | 变更前快照、变更后验收、失败即回滚 |
| 5 | **无 Root 边界** | 不承诺系统级特权数据；无 Root 拿不到的一律标 `null`/不可得 | 承诺做不到的事会诱导违规 Root/刷机 | 文档/面板承诺全局 CPU、原始网络字节等不可得字段 | 能力清单 + `null` 语义 + 明确"不可得清单" |
| 6 | **设备无关** | 核心逻辑只依赖标准 Android API/Linux 用户态；厂商差异只进 profile | 换机不该重写方法论与代码 | 核心代码/数据契约出现具体厂商名或机型假设 | 标准 API + OEM profile 分离（见 [MTH-002](01-assessment.md)） |
| 7 | **验收先行** | 先定义可验证标准（重启/soak/故障注入/恢复），再实施 | 没验收标准就无法判断"完成"，容易伪完成 | 以"看起来正常"替代"实测通过"；未跑 soak 就标完成 | 门禁 + 证据链；未实测写"待验证" |
| 8 | **密钥卫生** | token/口令/私钥/证书/备份口令不入库、不入日志、不入聊天/公网页面 | 手机服务器一旦泄露就是个人隐私与内网入口 | 文档出现真实端口/地址/凭据；日志明文 token | 密钥文件最小权限 + 脱敏 + 泄露先轮换（[GRD-006](../guardrails/GRD-006-secret-hygiene.md)） |
| 9 | **不复制 GPL** | 第三方只做参考或按许可使用；GPL 代码不复制进自有产物 | 避免许可污染与发布风险 | 直接拷贝 GPL 仓库代码/文件 | 只参考思路；可用库限定宽松许可（[GRD-010](../guardrails/GRD-010-license-compliance.md)） |
| 10 | **文档给 Agent 读** | 结论先行、决策表、可执行命令、检查清单、失败处理、稳定 ID | 项目长期由 Agent 迭代，可读性=可维护性 | 大段叙述无结论；无字段定义；无验收标准 | front matter + 机器索引 + 模板 + 校验命令（[MTH-009](08-agent-handoff.md)） |

**原则冲突时的优先级（从高到低）**：用户明确授权与红线 > 密钥卫生 > 可回退 > 最小权限 > 故障隔离 > 性能/功耗 > 使用便利。
无法判断时选**更保守**的一侧，并把选择写入 assumptions 与变更记录。

## 5. 非目标（明确不做）

- ❌ **不做日常主力机**：改造后通话/拍照/移动支付等职责不再保证；解锁/Root 会破坏完整性与部分金融 App。
- ❌ **不承诺原生 Linux**：没有成熟社区移植的机型不自行移植（人月起的工作量，且服务器关键驱动最难齐）。
- ❌ **不承诺容器/编排**：手机内核常见缺 `USER_NS`/`PID_NS` 或 cgroup 委派；容器必须真机探测通过才评估。
- ❌ **不默认解锁/刷机/Root**：B/C 路线只在评估门禁通过 + 设备所有者明确授权后作为例外执行。
- ❌ **不新增未授权公网暴露**：默认局域网；公网只经受控入口；外部服务（异地备份/监控/MFA/Tailscale 类）未获确认不接。
- ❌ **不把 Linux 服务器塞进 APK**：桥只做宿主桥；否则等于在 Android 里重做 Termux，风险与工程失控。
- ❌ **不伪造验收**：未实测不标完成；目标值与实测值分开记录；偏差与失败必须保留（[GRD-013](../guardrails/GRD-013-no-fake-acceptance.md)）。

## 6. 成功标准（DoD）

| 类别 | 标准 | 验收证据 |
|---|---|---|
| 功能 | 远程登录可用；核心服务可访问；状态聚合可用 | 命令输出 + 面板截图/接口返回 |
| 可用性 | 连续 7 天可达率 ≥99%；30 天无需现场干预（长期目标） | soak/监控记录（至少 24h 起步） |
| 自恢复 | 断电/重启后服务在目标时间内自动恢复（无 PC/ADB 介入） | 5 次重启实测记录与耗时 |
| 性能与资源 | 空载负载与温度在设备可接受范围；内存/存储不持续恶化 | 资源采样对比 T0 基线 |
| 散热与供电 | 满载 30 分钟不关机、不触温度墙；长期插电不鼓包/不异常老化 | 压力测试 + 电池策略核对 |
| 备份恢复 | 每日备份存在；恢复演练一次通过（RPO/RTO 达标） | `server-restore --verify` 类校验 + 演练记录 |
| 安全 | 只 loopback/局域网可达；无未授权公网端点；凭据不在仓库/日志 | 端口/权限清单核对 + 脱敏检查 |
| 可回退 | 每阶段有回滚步骤，且至少演练一次 | 回滚记录 + 恢复后验收 |
| 文档与 Agent | 换人/换 Agent 按文档可复现；校验命令全绿 | `toolkit validate --strict` + 链接检查 + 清单 |

> **判定规则**：只有**证据**能勾选 DoD；文档声称、代码存在、单次健康检查通过都不算完成。目标值（如资源/可用率）与实测值必须分列。

| 类别 | 状态（2026-11-11） | 证据/入口 |
|---|---|---|
| 无 Root + proot 服务器栈 | **已验证**：服务全量运行、重启自启有实测记录 | [当前状态](../docs/00-overview/当前状态.md)（案例实证） |
| 宿主遥测桥（`specialUse` FGS + loopback） | **已落地**：release 运行、重启验收通过；**24h soak 未完成** | [28 全栈规范](../docs/00-overview/28-全栈整体方案规范.md)、[33 Bridge 实施记录](../docs/50-bridge/33-Android-Bridge-MVP实施记录.md) |

| 桥的 mTLS/配对/token 轮换/限流加固 | **未完成（Phase 2 剩余）** | [当前状态](../docs/00-overview/当前状态.md) |

| B/C/D 路线 | **未采用**：B 因解锁门禁失败终止；C/D 无社区移植 | [02 可行性分析](../docs/10-device/02-可行性分析.md) |

**引用规则**：引用案例事实必须标 **"案例实证"** 并给相对链接（`../docs/...` 或 `../cases/...`）；通用结论必须能被新设备验证，不得把单机型结论伪装成普适结论。
**案例冻结**：`docs/`、`scripts/`、`android-bridge/`、`cases/` 是历史证据，只允许修正事实错误，不得为了"更好看"改写结论。

## 9. 变更传播

1. 本页的原则/边界变化 → 必须同步 [MTH-002](01-assessment.md) 决策条件、[MTH-003](02-roadmap.md) 门禁、[MTH-007](06-security.md) 安全底线，并更新术语表。
2. 新增"不承诺项"或"新增前提"属于**对外契约变化**，必须写 ADR 与变更记录。
3. 任何文档改动后运行：`python -m toolkit.repurpose validate --strict`、`python scripts/dev/check-links.py --strict-anchors`。
4. 详细扩展协议见 [MTH-009 Agent 交接](08-agent-handoff.md)。

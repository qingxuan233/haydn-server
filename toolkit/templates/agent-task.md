# （模板示例）Agent 任务单

> 模板使用说明：`toolkit/templates/agent-task.md`。任务单是给 subagent/新会话的
> 自包含上下文；禁止只给"帮忙优化一下"这类模糊目标。

## 0. 风险分级与需求基线

| 级别 | 判定 | 例子 | 开工前置 |
|---|---|---|---|
| L | 单文件/低影响/可逆 | 文档措辞澄清、模板字段排序、补一条索引 | 直接开工；记 backlog 即可 |
| M | 多文件/契约或跨层联动 | 新增模板、改 validate 检查、改 schema/命令 | 先填[需求基线卡](request-card.md)并获 DRI 批准 |
| H | 不可逆/设备写操作/红线或协议 MAJOR | Root/刷机、改权威顺序、删数据、对外发布 | 需求卡 + DRI 批准 + 回滚演练 + 观察期 |

```text
需求基线卡：M/H 必填（模板 toolkit/templates/request-card.md），结论与 risk 字段登记 backlog.json
风险判定人：任务发起者；Agent 不得自行下调风险级别或豁免
```

## 1. 目标（可验收）

```text
目标：<一句话，能被命令或文件验证>
不做：<明确排除项，避免范围膨胀>
```

## 2. 输入与上下文

| 项 | 内容 |
|---|---|
| 相关文档 | `<MTH/PIT/GRD 相对路径>` |
| 当前状态 | `<profile/assessment/日志相对路径>` |
| 前置条件 | `<ADB/备份/工具版本/权限>` |

## 3. 写范围（互斥）

```text
允许写：<目录/文件前缀列表>
禁止写：<冻结目录/他人范围>
产物：<生成物路径，gitignored 需标注>
```

## 4. 步骤

1. 只读核对现状与影响面；
2. 在共享任务板 claim（多 Agent 时），记录 write_scopes；
3. 按最小步修改，每步可回滚；
4. 运行验收命令；
5. 更新索引/文档/backlog（如契约变化）。

## 5. 验收命令

```bash
python -m toolkit.repurpose validate --strict
python -m toolkit.repurpose index --json
python -m unittest discover -s toolkit/tests -t . -v
```

## 6. 报告格式（五段）

```text
1) 结论一句话：做了什么、到什么状态
2) 证据清单：命令 + 退出码 + 关键输出 + 路径:行号
3) 事实分级：已核验（附证据）/ 推断（写依据与验证方式）/ 未知（标"待验证"并进 backlog）
4) 未完成与风险：没做什么、为什么、影响面、回滚方式
5) 下一步建议
```

> **禁止用语**：「应该/可能/大概/看起来/肯定可以/前文写过所以肯定对」不得作为结论收尾；需要表达不确定性时写成「推断，依据 X，验证方式 Y」。失败如实上报，不得包装成部分成功。

## 7. 关联

```text
负责人：<agent 名称>
任务板 ID：<task-id>
依赖：<其他任务/文档>
```

## 8. 停止条件（命中任一立即停）

1. 与红线/协议冲突，或规则之间矛盾需要裁决；
2. 需要越权（边界表第二/三档）或凭据/真机/外部授权；
3. 证据不足，无法验证当前结论；
4. 阅读/时间预算用尽；
5. 同一问题连续 2 次失败且原因不明；
6. 单任务步数逼近上限（正常 3~10 步，>20 步必须停）；
7. 发现自己在"为了让检查通过"而调整检查本身。

> 停下动作：如实报告状态 + 给出 2~3 个带权衡的选项。**停下不是失败，隐瞒才是失败。**

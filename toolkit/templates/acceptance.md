# （模板示例）验收清单

> 模板使用说明：`toolkit/templates/acceptance.md`。验收是"证据驱动"的：
> 每一项都要能指向命令输出/记录/相对路径，禁止"文档声称通过"；目标值与实测值必须分栏。

## 1. 验收前提

| 项 | 要求 | 状态 |
|---|---|---|
| 备份与回滚 | 备份可恢复、回滚路径演练过 | `<pass/fail/pending>` |
| 基线 profile | `assess` 有结论、unknown 已标注 | `<pass/fail/pending>` |
| 变更范围 | 与批准范围一致，无冻结目录改动 | `<pass/fail/pending>` |

## 2. 三态退出码契约（强制）

| 退出码 | 含义 | 判定与处置 |
|---|---|---|
| `0` | VERIFIED：全部验收项实测通过 | 才能标"已验证/完成" |
| `3` | SKIPPED：存在未执行/未验证项 | 只能标"部分验证/待验证"；列出跳过项与原因 |
| `4` | FAILED：任一项实测不通过 | 必须回滚或修复后重跑；不得降级为"部分通过" |

> 最常见的误读是把 `3` 当成"通过"；**诚实降级：宁可报"没验证"，也不假装验证过。**

## 4. 反例自证（检查真的会拦）

```text
必做：造一个"应当失败"的反例，证明验收检查本身有效，而不是必然合格的自证。
- 反例输入：<违规配置/坏 front matter/错误字段/被剪除的检查项>
- 期望结果：检查 exit≠0 或 FAILED（记录实际输出）
- 若反例也"通过"：说明检查是空的，验收结论无效，先修检查再验收
```

# 05 · B 路线执行手册（解锁 + Root + chroot）

> **当前状态（2026-11-10 实测）**：设备仍为 **锁定（`flash.locked=1`）且未 Root**，区域 **CN（国行）**。
> 方案 A 已运行（Termux sshd 2222 + proot + 多个服务），**一旦解锁会全部清空**。
> 本手册的执行顺序是：**先验证解锁可行性（非破坏性）→ 备份 → 解锁 → Root → chroot**。任何一步不通过就停下，不要硬闯。

## 1. Gate B0：解锁可行性验证（非破坏性，约 10 分钟）

> **原则**：只做"申请/绑定/工具识别"这类检查。**Mi Unlock 只有在解锁成功那一刻才会抹数据**；失败提示不会清数据。
> 若 Gate B0 任一步出现"不支持/不可解锁"，**立即停止 B 路线**，转 §9 的 A+ 方案。

### B0-1 手机端：检查小米社区 App 是否有解锁入口

1. 打开手机上的**「小米社区」App**（本机已安装 `com.xiaomi.vipaccount`）；
2. 登录**与手机相同的小米账号**（账号需满足：注册 > 30 天、绑定手机号）；
3. 「我的」→ 右上角设置 → **社区区域**：尝试选 **Global / 全球**（若无法修改，记录现象）；
4. 「我的」→ 查找 **Bootloader 解锁 / 解锁申请** 入口。

| 现象 | 判读 |
|---|---|
| 能看到「申请解锁」按钮，可点击 | 🟡 可能可行 → 继续 B0-2 |
| 提示「该机型不支持 / 地区不支持 / 暂无资格」 | 🔴 **国行受限，B 路线不可行** → 转 §9 |
| 完全没有解锁入口 | 🔴 同上（记录 App 版本与区域） |

### B0-2 手机端：绑定账号与设备

1. `开发者选项` → 打开 **OEM 解锁**、**USB 调试**（均已允许）；
2. 插入 SIM 卡、关闭 Wi-Fi、开启移动数据（绑定必须走移动网络）；
3. `开发者选项` → **设备解锁状态** → 「绑定账号和设备」；
4. 记录提示：

| 现象 | 判读 |
|---|---|
| 「绑定成功 / Mi Account 已关联」 | 🟢 继续 B0-3 |
| 「无法添加，请先在小米社区申请授权」 | 🟡 先完成 B0-1 申请，再回来绑定 |
| 「该设备不支持解锁 / 账号不满足条件 / 地区不匹配」 | 🔴 **B 路线不可行** → §9 |

### B0-3 PC 端：用 Mi Unlock 工具验证（关键一步）

工具已备好：`tools\mi-unlock\miflash_unlock.exe`（官方 7.6.727.43，已解压校验）。

```powershell
# 1) 手机进 fastboot（也可手动：关机后 音量下 + 电源）
powershell -ExecutionPolicy Bypass -File scripts\adb.ps1 reboot bootloader

# 2) 确认 fastboot 能识别设备
tools\platform-tools\fastboot.exe devices

# 3) 启动解锁工具
start tools\mi-unlock\miflash_unlock.exe
```

在 Mi Unlock 工具里：
1. 登录**与手机同一账号**；
2. 看到 "Phone connected"（若没有：装驱动 `tools\mi-unlock\MiUsbDriver.exe`、换 USB 2.0 口/原装线）；
3. 点击 **Unlock**。

| 工具提示 | 判读与下一步 |
|---|---|
| `Unlock anyway` / `Please unlock N hours later`（72/168 小时） | 🟢 **可解锁**：等待期满 → 进入 §3 正式解锁 |
| `Current account is not bound to this device` | 🟡 回 B0-2 重新绑定（必须在移动数据下） |
| `The place where the account is registered does not match...` | 🔴 账号区域与机区域不符 → 受限 |
| `Your account does not meet the requirements` / 不支持 / 区域不支持 | 🔴 **B 路线不可行** → §9 |

> **验证结束后返回系统**：`tools\platform-tools\fastboot.exe reboot`（或长按电源 10 秒）。

## 5. 阶段 B-3：chroot Debian + s6/supervisord

> 目标：在 Android 内核之上获得"真 Linux 文件系统与服务管理"，**不是**容器（内核已否决）。

### 5.1 准备 Debian arm64 根文件系统

```bash
# 手机 root shell 内（Termux 里 su 或 adb shell su）
mkdir -p /data/local/linux/debian
# 下载 Debian arm64 rootfs（官方镜像/容器镜像导出均可），解压：
tar xzf debian-rootfs-arm64.tar.gz -C /data/local/linux/debian
```

> 根文件系统建议 ≥ 4GB（`/data` 可用 193GB，充足）。

### 5.2 进入 chroot（手动验证）

```bash
su -c '
  R=/data/local/linux/debian
  mount --bind /proc $R/proc
  mount --bind /sys  $R/sys
  mount --bind /dev  $R/dev
  mount --bind /dev/pts $R/dev/pts
  cp /etc/resolv.conf $R/etc/resolv.conf
  chroot $R /bin/bash -c "apt update && apt install -y openssh-server s6 nginx htop"
'
```

> 若 `chroot` 报 `Operation not permitted`：Magisk 域缺少 `CAP_SYS_CHROOT` 或 SELinux 限制 → 改用 Termux 内 `su` 执行并记录；仍失败则记录（这是 B 路线关键验收点）。

### 5.3 服务管理（s6）

```
chroot 内 s6 服务树示例：
/etc/s6/sshd/run        → /usr/sbin/sshd -D -e
/etc/s6/nginx/run       → /usr/sbin/nginx -g 'daemon off;'
/data/local/linux/debian/etc/s6/...   由 s6-svscan 扫描
```

自启（Magisk 模块或 `service.sh`）：

```bash
#!/system/bin/sh
# /data/adb/modules/linux-chroot/service.sh
sleep 20
R=/data/local/linux/debian
mount --bind /proc $R/proc
mount --bind /sys  $R/sys
mount --bind /dev  $R/dev
mount --bind /dev/pts $R/dev/pts
chroot $R /usr/bin/s6-svscan /etc/s6 &
```

### 5.4 网络与入口

| 入口 | 用途 | 说明 |
|---|---|---|
| chroot sshd :22 | 主入口（真 Linux 环境） | 需端口不被占用；仅公钥登录 |
| Termux sshd :2222 | 应急入口 | 保持 A 方案习惯，作为后备 |
| Tailscale | 远程访问 | 不做公网端口映射（ADR-004） |

## 7. 回滚手册（B 路线专用）

| 场景 | 操作 |
|---|---|
| Root 后 bootloop | `fastboot flash boot backup\firmware\boot.img`（当前 slot）→ `fastboot reboot` |
| 系统分区损坏 | MiFlash 刷官方完整 fastboot ROM（**不要勾选 "clean and lock"**，除非确认 ROM 与区域完全一致） |
| chroot 服务异常 | 删 `/data/adb/modules/linux-chroot/` → 重启；Android 系统不受影响 |
| 想回到"解锁但未 Root" | 刷回原厂 `boot.img`；**不建议重新上锁**（有变砖风险） |
| 彻底放弃 B | 刷官方 ROM + 保留解锁状态，回到 A 方案（数据从 `backup/` 恢复） |

> **纪律**：任何刷机前确认 ① 固件包已校验 ② fastboot 可用 ③ 电量 > 50% ④ 有回滚包。

## 9. 若 Gate B0 失败：A+ 无 Root 深度优化方案

> 国行若确实无法官方解锁，B 路线终止。**把 A 方案做深做稳**同样能达到"家用轻量服务器"目标。

| 优化项 | 做法 | 收益 |
|---|---|---|
| 服务精简与自愈 | proot + supervisord（autorestart）；Termux:Boot + wake-lock 双保险 | 稳定性 |
| 远程与网络 | Tailscale always-on；路由器 DHCP 保留；关闭随机 MAC | 可远程、IP 不漂移 |
| 显示/省电 | 熄屏 15s、亮度最低、动画归零、关 AOD | 功耗/温度 |
| 充电保护 | HyperOS「智能充电保护」开启（Root 才能用 ACC） | 延缓电池鼓包 |
| Debloat | `pm disable-user` 逐包禁用（可逆） | 降负载 30–50% |
| 温度监控 | `scripts` 采集 + 定时记录 + 告警 | 提前发现降频 |
| 服务边界 | 单实例 ≤ 3–5 个服务，避免 OOM | 稳定 |
| 数据备份 | rsync 到 PC/NAS + 每周演练 | 数据安全 |
| 升级策略 | 冻结固件、关自动更新 | 避免 OTA 破坏 |

> A+ 方案可直接写入 `docs/00` 的 P5 阶段并执行，**不需要任何破坏性操作**。

## 4. 下一步（Phase 0 → Phase 1）

### Phase 0：构建环境（0.5 天）
- 安装 Android SDK cmdline-tools + platform 34/35 + build-tools；Gradle wrapper；
- 创建 `android-bridge/` 工程（Kotlin，minSdk 29，target 35，包名 `com.qingxuan.bridge`）；
- Gate G0：`assembleDebug` 产出可安装 APK。

### Phase 1：MVP（2–3 天）
- BootReceiver（BOOT_COMPLETED / MY_PACKAGE_REPLACED）+ `specialUse` Foreground Service + `START_STICKY`；
- 本地 HTTPS（127.0.0.1:3099）：`/v1/health`、`/v1/version`、`/v1/status`；
- token + 证书 pin + 限流 + GET-only；
- Collectors：Battery/Wifi/Build/Memory/Disk/Thermal/Packages；
- Server `bridge_client.py` + `/api/sysinfo` 合并 + `bridge_source`/`bridge_age_s`；
- Gate G1：APK 安装、启动、5 次重启后自启/存活。

### Phase 2（后续）
- UsageStats/NetworkStats/Display/Keyguard；
- mTLS/配对/证书轮换；MIUI 白名单自动化；
- `server-ops bridge status`、DSH 技能/AGENTS；
- 24h soak + 故障注入。

## 7. 护栏（必须遵守）

1. **不 Root、不刷机、不解锁 BL**；不装系统/priv-app。
2. **不卸载系统包**；不执行 `am kill-all`；不改 Android 系统设置（ADB 优化除外）。
3. **不把 Bridge token/证书/DSH token/备份口令**写入日志、聊天、公网页面。
4. **DSH 不直连 Bridge、不持 token、不试图启动 App**；只走 Server API/server-ops。
5. **写操作走 server-ops Tier2**（`--confirm` + 快照 + 审计）；Tier3 只人工 SSH。
6. **外部服务**（Uptime Kuma/异地备份/MFA/Tailscale）未获确认不做。
7. 不重装服务器除非按 docs/17；重装前先备份并确认回滚。

## 8. 验收门禁（Phase 0/1 最低）

| Gate | 标准 |
|---|---|
| G0 | APK 可构建、可安装 |
| G1 | 5 次重启后 Bridge FGS 自启；`/v1/health` 200 |
| G2 | `/api/sysinfo` 出现 `bridge_source=bridge` 且电池/WiFi 非空或明确 null |
| G3 | 停 Bridge → 服务器回退 `termux`，Console 不报假数据 |
| G4 | 非 token 请求 401；仅 loopback 监听；无 shell 端点 |
| G5 | 24h 可用率 ≥99%；无崩溃循环；DSH/服务器不受影响 |

## 9. 常用只读命令

```bash
# 服务/健康
server-ops status
server-ops health
server-ops logs dsh --lines 100

# 当前状态 API
curl -s http://127.0.0.1:8080/api/sysinfo | head
curl -s http://127.0.0.1:8080/api/ops?n=5 | head

# Bridge（Phase 1 后）
curl -sk https://127.0.0.1:3099/v1/health
curl -sk -H "Authorization: Bearer <token>" https://127.0.0.1:3099/v1/status | head
```

> 不要把 token 写进聊天/日志；示例中占位符仅文档用。

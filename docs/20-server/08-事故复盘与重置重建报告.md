## 1. 事故经过与根因

### 1.1 现象

2026-11-10 约 12:39，手机重启后进入 **无限开机动画 + RescueParty**：

```
sys.boot.reason = reboot,rescueparty
init.svc.bootanim = running
system_server 反复启动/崩溃（每 ~5 秒）
```

### 1.2 根因（crash buffer 证据）

```
*** FATAL EXCEPTION IN SYSTEM PROCESS: main
java.lang.RuntimeException: Required services extension package is missing,
check config_servicesExtensionPackage.
    at com.android.server.pm.PackageManagerService.getRequiredServicesExtensionPackageLPr
```

- 触发点：此前 aggressive debloat 用 `pm uninstall --user 0` 移除了 **`com.google.android.ext.services`**（Android 系统启动必需包）。
- 该包被 `config_servicesExtensionPackage` 引用；PackageManagerService 构造时发现缺失 → `system_server` 直接 crash → 循环 → 触发 RescueParty。
- 由于 `system_server` 在 PackageManagerService 初始化阶段就崩溃，**`pm` 服务根本来不及注册**：
  - `adb shell pm` → `Can't find service: package`
  - 无法在线 `install-existing` 恢复，只能清数据 / 刷机。

### 1.3 处置

1. 尝试 ADB 抢窗口恢复 → `pm` 不可用（失败）；
2. 用户执行 **恢复出厂设置（清除数据）**；
3. 数据影响：
   - 手机 `/data`、`/sdcard` 全部清空（Termux/proot/服务器、照片等）；
   - 服务器数据依赖已有备份重建（见 §3）；
   - 本项目文档、采集快照、服务器 `/root`+`/etc` 备份均在 PC `backup/` 中保留。

### 1.4 复盘结论（已固化为安全红线）

| 红线 | 说明 |
|---|---|
| ❌ 禁止 uninstall 任何系统包 | 只允许 `pm disable-user`（包仍"已安装"，缺失检查不会触发） |
| ❌ 禁止卸载/禁用产品必需的 Google 扩展包 | 包含 `com.google.android.ext.services`、`ext.shared` 等，见保护名单 |
| ✅ 第三方数据安装 App 可以 uninstall | 可从系统分区 `install-existing` 恢复 |
| ✅ 每批变更后重启验证 | 禁止"改完不重启就继续" |
| ✅ 变更前有备份与回滚路径 | 服务器配置备份、Ubuntu base 镜像、恢复脚本 |

> 保护名单已写入 [scripts/adb/optimize-server-profile.ps1](../../scripts/adb/optimize-server-profile.ps1) 的 `$protected` 列表（ext.services / providers / systemui / settings / 网络栈 / 电话 / 安全中心等）。

## 3. 服务器重建（13:30–14:40）

### 3.1 重建物料

| 物料 | 来源 | 用途 |
|---|---|---|
| Termux / Termux:Boot APK | GitHub Release v0.118.3 / v0.8.1（镜像下载） | 运行环境与开机自启 |
| `ubuntu-base.tar.gz`（28.5MB） | `backup/dsh/` | Ubuntu 24.04 arm64 根文件系统 |
| `a-route-20261110-1100.tgz`（54.5MB） | `backup/a-route/` | 服务器 `/root` + `/etc`（Gitea/Syncthing/WebDAV/frp/nginx 配置与数据） |
| proot 离线包 | TUNA Termux 镜像（proot + libtalloc + libandroid-shmem） | 避开 Termux apt 卡死 |
| Node 24.22.2 | TUNA nodejs-release 镜像 | DSH 运行时 |
| `@deepseek-ai/dsh 0.2.2-rc.1` | npm registry | DSH 本体 |

### 3.2 关键步骤与踩坑

| 步骤 | 问题 | 修复 |
|---|---|---|
| Termux apt install proot | `pkg update` 卡死、dpkg 锁 | 放弃 apt，改为解包 `.deb` 离线安装 proot |
| Ubuntu apt update | `/etc/resolv.conf` 是坏软链、ports.ubuntu.com 解析失败 | 删软链写真实 resolv.conf；apt 源统一 TUNA `ubuntu-ports` |
| nginx 安装 | dpkg postinst 因无 systemd 失败 | `/usr/sbin/policy-rc.d` 返回 101 + `systemctl` shim，nginx 功能可用 |
| gitea 启动 | `git not found` | `apt-get install git` |
| webdav | pip 与系统 blinker 冲突 | `pip3 install --ignore-installed wsgidav cheroot` |
| sshd | `Missing privilege separation directory: /run/sshd` | 创建 `/run/sshd` + `ssh-keygen -A` |
| **proot 周期性崩溃（最关键）** | `/sdcard` 绑定 sanitize 失败 → `compare_paths2 assertion length1 > 0` → SIGABRT，整个服务栈每隔几分钟消失 | **ubuntu.sh 不再绑定 `/sdcard`**；rootfs 内 `/sdcard -> /hosthome/sdcard` 软链；服务必须由 **Termux App/开机脚本上下文**启动（`run-as` 上下文不稳定） |
| DSH 安装 | bin.js 被软链穿透覆盖 / arm64 原生模块缺失 / 包装器命中 Node18 | 重装包；补 `node-addon-require-builtin-linux-arm64-gnu`；包装器显式调用 Node24 |
| DSH 公网入口 | `$host` 丢端口导致 trusted-host 不匹配 → `/api` 403 | nginx 使用 `$http_host`；DSH 加 `--public-url`/`--trusted-host` |

## 6. 遗留事项与风险

| 项 | 说明 | 建议 |
|---|---|---|
| 无锁屏 | 设备失去锁屏保护（换取开机自启） | 家用局域网环境可接受；若外出携带需权衡 |
| 服务器备份路径 | 因 proot `/sdcard` 绑定缺陷，`/sdcard` 现指向 `/hosthome/sdcard`（Termux 私有目录），备份不再落到共享存储 | 已可正常工作；若需真共享存储，后续用 `adb pull` 或改良绑定 |
| SSH 私钥曾泄露 | 会话中贴过私钥 | 建议重新生成密钥并替换 |
| 公网暴露面 | 公网经 frp 对外开放（地址/端口见运维私密记录） | 建议限制来源 IP / 定期更新 token；Basic Auth 密码强度 |
| 电池保养 | 长期插电 | 手机 GUI 开启「智能充电保护」 |
| 稳定性观察 | 服务器 14:40 起稳定运行 | 建议 24 小时后跑 `phone-health.ps1` 复核 |

## 7. 回滚与灾难恢复

- **服务回滚**：`server-dsh stop` / 从 supervisord.conf 删除 `[program:dsh]`；或恢复 `/root/server/etc/supervisord.conf.bak*`。
- **nginx 回滚**：`sites-available/dsh-tls` 有 `.bak-dsh-*` 备份（重建时生成的）；`nginx -t && nginx -s reload`。
- **服务器数据恢复**：`backup/a-route/a-route-20261110-1100.tgz` 解包到 proot rootfs（`/root` + `/etc`）；`ubuntu-base.tar.gz` 重建 rootfs。
- **彻底重置**：小米 Recovery「清除数据」→ 按本报告 §3 重建（Termux APK 与离线 deb 已在 `tools/` 与文档记录中）。

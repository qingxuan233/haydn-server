## 1. 前置与工具

### 1.1 PC 侧

| 项目 | 要求 |
|---|---|
| 系统 | Windows 10/11 + PowerShell 5.1+；**脚本/构建路径必须是 ASCII**（仓库已改名 `haydn-server`） |
| ADB/fastboot | `tools/platform-tools/`（gitignored，可重下） |
| 脚本 | `scripts/adb/`（设备/ADB 操作）、`scripts/termux/`（Termux 侧）、`scripts/server/`（proot 服务器脚本）、`scripts/dev/`（文档检查） |

### 1.2 手机侧（一次性）

1. 设置 → 我的设备 → 全部参数 → 连续点击“HyperOS 版本”7 次，开启开发者选项；
2. 开发者选项 → 打开「USB 调试」；连接 PC 时弹窗勾选“一律允许”；
3. 开发者选项 → 打开「USB 调试（安全设置）」——MIUI 下缺少它会导致 ADB 权限受限；
4. 研究机保持**无锁屏凭据**（PIN/图案/密码 = 无）：FBE 开机即解密，Termux:Boot 才能无人值守触发；
5. 电池策略：Termux、Termux:Boot 设为「无限制」，允许自启动；`termux-wake-lock` 常驻。

### 1.3 服务器侧

- Termux（F-Droid/GitHub 版，勿用已停更的 Play 版）+ Termux:Boot；
- proot Ubuntu 24.04 rootfs 位于 `~/ubuntu`；服务由 `supervisord` 管理（**不用 systemd**）；
- `scripts/server/` 下为可入库脚本；`/root/server` 下的运行态配置由备份恢复。

### 1.4 构建 Bridge APK 的前置

```powershell
# 检查 JDK（17/21，build.ps1 自动探测）与 SDK（tools/android-sdk）
java -version
$env:ANDROID_HOME   # 若为空，build.ps1 会自动探测仓库内 tools/android-sdk

# 构建（产物在 android-bridge/build/，gitignored）
powershell -NoProfile -ExecutionPolicy Bypass -File android-bridge\build.ps1
```

- 无 Gradle：`build.ps1` 用 aapt2 + javac + d8 + zipalign + apksigner；
- 产物：`android-bridge/build/bridge.apk`（release 签名，约 25KB）+ `bridge.crt`；
- 路径含中文会直接报错提示（历史原因：aapt2 不支持中文路径）。

## 3. 常用运维操作

### 3.1 服务管理（server-ops / supervisorctl）

```bash
server-ops status                  # 汇总状态
server-ops health                  # 健康检查（端口/HTTP/证书/磁盘）
server-ops restart <service> --confirm   # 受控重启（快照 + 审计）
server-ops logs <service>          # 查看日志
supervisorctl status               # 底层状态（12 项）
supervisorctl restart <service>    # 紧急情况下直连
```

> 纪律：写操作优先走 `server-ops`（带确认与审计）；Tier3 破坏性操作只走人工 SSH。

### 3.2 Console 入口

| 入口 | 地址 |
|---|---|
| 总览 | `http://<LAN-IP>:8080/` |
| 详情 | `http://<LAN-IP>:8080/?view=details` |
| TLS | `https://<LAN-IP>:8443/` |
| 手机状态 | 总览/详情内的电池、WiFi 等卡片来自 Bridge API |

### 3.3 DSH 入口

```bash
server-dsh status      # 状态
server-dsh url         # 公网 /app/?token=…（token 每次重启变化）
server-dsh restart     # 受控重启
```

- 对用户统一用 **`/app-login`**（302 → 稳定登录页），不要收藏带 token 的 URL；
- `dsh-guard` v1.2 只在 `supervisorctl` 为 RUNNING 时才做 HTTP 健康检查，避免开机误重启；
- DSH 不持有 Bridge token，不直接执行手机特权操作。

### 3.4 Bridge 状态检查

```bash
server-ops bridge status     # 手机桥接状态（API/字段/延迟）
curl -s http://127.0.0.1:8000/api/sysinfo | python3 -m json.tool | head -40
```

- Bridge 只监听回环 + TLS + token + pin，**永不公网监听**；
- 升级 APK 时保留 token 与权限设置（release 签名，`debuggable=false`）；
- 若 Console 手机状态字段缺失，先查 Bridge 是否在线，再查权限（usage 等）。

### 3.5 备份与恢复

| 操作 | 命令 | 说明 |
|---|---|---|
| 每日备份 | `server-backup` / `server-backup-sessions` | 加密，含会话数据；每日自动 |
| 找回备份列表 | `server-ops status`（备份卡片）或查看 `/root/server/backups/` | — |
| 校验 | `server-restore --verify` | 解密 + 解包校验 |
| 恢复 | `server-restore --from <file> --target <dir> --yes` | 只走 CLI，防误操作 |
| 换机/重建 | 见 [17 重建手册](17-研究平台环境构建手册.md) | 物料 + 流程 |

> 备份不得只留设备本地；PC 侧另存一份（`backup/` 已 gitignore，**不要**提交/上传明文）。

### 3.6 换机或重装服务器

按 [17 重建手册](17-研究平台环境构建手册.md) 执行；迁移顺序：
Android 基础 → Termux/proot → rootfs → 服务器备份（`/root`+`/etc`）→ DSH → Console → Bridge → 验证（§2.2）。

### 3.7 Android 侧资源让渡与保活（无 Root）

```powershell
# 研究 App 静默 + Termux 保护 + freezer/logcat 重放
powershell -ExecutionPolicy Bypass -File scripts\adb\adb-server-resource.ps1 -Status
powershell -ExecutionPolicy Bypass -File scripts\adb\adb-server-resource.ps1 -Quiet
powershell -ExecutionPolicy Bypass -File scripts\adb\adb-server-resource.ps1 -Restore

# 重启后一键：Shizuku + appops/freezer/logcat 重放（可选开 5555）
powershell -ExecutionPolicy Bypass -File scripts\adb\after-reboot-android.ps1
```

> `am kill-all` 永久禁止（曾导致 Termux/proot 服务全灭，见 R-17）。系统包只 `disable`/`suspend`，**禁止 uninstall**（见 R-19）。

## 4. 优化调优（每项可单独回滚）

> 原则：**一次只改一项**，改完观察 24h（温度/耗电/稳定性），记录到 [01 设备档案](../10-device/01-设备档案.md) 的变更表。

### 4.1 屏幕与显示（省电降温，效果最大）

```bash
adb shell settings put system screen_off_timeout 15000     # 15 秒熄屏
adb shell settings put global stay_on_while_plugged_in 0
adb shell settings put system screen_brightness 10         # 低亮度
adb shell settings put system screen_brightness_mode 0     # 手动
adb shell settings put system peak_refresh_rate 60         # 120Hz→60Hz
```

### 4.2 动画（降低渲染开销）

```bash
adb shell settings put global window_animation_scale 0
adb shell settings put global transition_animation_scale 0
adb shell settings put global animator_duration_scale 0
```

### 4.3 网络

- 首选：路由器给手机 MAC 做 DHCP 静态租约（避免 IP 漂移导致 frp/SSH 断）；
- 备选：系统内静态 IP（`192.168.10.x/24`，网关/DNS 按家里路由器）；
- `wifi_sleep_policy=2`（WiFi 不休眠）；关闭随机 MAC。

### 4.4 电池与充电（长期插电必做）

| 层次 | 做法 | 说明 |
|---|---|---|
| 系统 | 设置 → 电池 → 充电保护/智能充电 | 无 Root 下唯一手段；版本差异大 |
| Root | ACC（Advanced Charging Controller） | **本机不可用**（无 Root，battery sysfs 不可读） |
| 物理 | 通风、远离热源、不覆盖 | 最有效且零成本 |
| 监控 | `scripts/adb/phone-health.ps1` 记录温度/健康 | 阈值：CPU ≤ 70 °C、电池 ≤ 40 °C |

### 4.5 CPU 与温控

- 服务器场景建议 `schedutil`（默认）；**不要长期 performance**；
- 调 governor / 限频 / I/O 调度 / zram / sysctl **全部需要 Root → 本机不可用**，这也正是 A+ 路线的能力边界（见 [09 性能优化](09-性能优化方案与可行性分析.md) §4E）。

### 4.6 Debloat（免 Root 可逆）

```bash
adb shell pm list packages -e | grep -E 'miui.video|xiaomi.shop|miui.newhome'
adb shell pm disable-user --user 0 com.miui.video
adb shell pm enable com.miui.video        # 恢复
```

- **只禁用明确不用的应用**，每批 3–5 个并观察；保护名单见 `scripts/adb/optimize-server-profile.ps1` 的 `$protected`；
- 系统包被 MIUI `canBeDisabled` 拦截属正常安全限制，不再尝试绕过。

### 4.7 日志与磁盘

- supervisor 日志按 `maxbytes` 轮转；服务器日志 `/root/server/logs/`；
- `df -h` 检查 `/data`；`/var/cache/apt` 定期 `apt-get clean`（可释放数百 MB）。

## 5. 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `adb devices` 显示 `unauthorized` | 手机未授权 | 手机端点“允许”并勾选“一律允许”；重插线 |
| `adb devices` 为空 | 线/驱动/USB 调试 | 换线；装驱动；确认调试开关 |
| `device offline` | adb server 异常 | `adb kill-server && adb start-server` |
| SSH 连接被拒 | sshd 未运行/端口不对 | 服务器内 `pgrep sshd`；确认 2222；`server-ops status` |
| SSH host key 变更 | 重装/重置后指纹变化 | `ssh-keygen -R "[<LAN-IP>]:2222"` |
| Termux 进程被杀 | HyperOS 省电 | 电池策略“无限制” + `termux-wake-lock`；`restart-termux-services.ps1` |
| 服务每几分钟整体消失 | proot `/sdcard` 绑定触发 `compare_paths2` 断言 | 不绑定 `/sdcard`（`ubuntu.sh` 已固化）；由 Termux:Boot 启动 |
| 开机不自启 | 锁屏凭据导致 FBE 延迟 `BOOT_COMPLETED` | 保持无锁屏；或开机后解锁一次 |
| 8080 起来了但服务不是 12/12 | 启动未完成/guard 误判 | 等 111s；`supervisorctl status`；`server-ops restart <svc> --confirm` |
| Bridge 状态字段缺失 | Bridge 未在线/权限被重置 | `server-ops bridge status`；重授权 usage；查 APK 是否 release 版 |
| DSH `/app-login` 503 | DSH 仍在启动或被 guard 重启 | 等 1–2 分钟；查 `dsh-guard` 日志；`server-dsh restart` |
| `/app/api` 403 | nginx `$host` 丢端口 / trusted-host 不匹配 | nginx 用 `$http_host`；DSH 带端口 trusted-host |
| apt 卡住/持锁 | Termux/网络慢 | 杀 apt；必要时用离线 `.deb`（见 [17 §Phase 2](17-研究平台环境构建手册.md)） |
| 磁盘告警 | 日志/缓存增长 | 轮转 + 清缓存 + `df -h` 复核 |
| 卡米/bootloop | 系统包被误删或刷机失败 | 只可能是历史问题：恢复模式清数据重建（见 [08 事故复盘](08-事故复盘与重置重建报告.md)） |

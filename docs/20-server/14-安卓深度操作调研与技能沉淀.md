## 3. 本机实测记录（可复现）

### 3.1 MIUI 拦截 `adb install`：根因与绕过

```text
$ adb install shizuku.apk
Failure [INSTALL_FAILED_USER_RESTRICTED: Install canceled by user]
# logcat 证据：com.miui.securitycenter/com.miui.permcenter.install.AdbInstallActivity
```

- 尝试直接禁用该 Activity：
  `pm disable --user 0 com.miui.securitycenter/com.miui.permcenter.install.AdbInstallActivity`
  → `SecurityException: Shell cannot change component state ...`（系统保护，失败）
- 成功方案：**唤醒屏幕 + uiautomator 轮询 + `input tap` 点「继续安装」**（脚本见 §6）。
- 注意：需临时延长亮屏；点按识别基于中文按钮文案（`继续安装/安装/允许/确定`）。

### 3.2 Shizuku 安装与启动（v13.6，无 Root）

```text
# 安装：MIUI 弹窗自动确认后成功
adb install -r -t -g shizuku.apk        # 会被拦截 → 用脚本点按后成功

# 启动：v13.6 不是旧版 start.sh，而是 App 内「查看指令」给出的 libshizuku.so：
APK=$(adb shell pm path moe.shizuku.privileged.api | sed 's/package://')
adb shell "${APK%base.apk}lib/arm64/libshizuku.so"
# 输出：shizuku_server pid is 21483 / shizuku_starter exit with 0
```

- 状态：`ps -A` 可见 `shizuku_server`（uid=shell）；App UI 显示「Shizuku 正在运行（adb，已授权 0 个应用）」。
- **重启后需重新启动**（用 PC ADB 或无线调试；App 内无线调试启动需 UI 配对）。
- 官方提醒：MIUI 需在开发者选项开启 **"USB 调试（安全设置）"**；无线调试启动需把通知样式切到 Android（MIUI 限制）。

### 3.3 自建 ADB over TCP（手机自己控制自己）

```bash
# PC 端（只需一次，重启失效）：
adb tcpip 5555
# proot Ubuntu 内：
apt-get install -y android-tools-adb
mkdir -p /root/.android && chmod 600 /root/.android/adbkey   # 复制 PC 的 adbkey/adbkey.pub
adb kill-server && adb start-server
adb connect 127.0.0.1:5555
adb -s 127.0.0.1:5555 shell 'id'     # → uid=2000(shell) context=u:r:shell:s0
```

- 实测：WiFi IP 从 `.143` 变到 `.159` 后仍可用；公网入口不受影响。
- 安全：`adb tcpip` 会在 LAN 暴露 adbd（需 adbkey 认证，但仍属扩大攻击面）；用完可 `adb usb` 恢复。

### 3.4 深度命令能力（本机）

| 命令 | 结果 |
|---|---|
| `cmd -l` | 输出数百服务，含 `HyperPackageManager`、`MiuiWifiService` 等小米私有服务 |
| `dpm list-owners` | `no owners`（可 `set-device-owner`，但**未测**，移除成本高） |
| `pm list users` | 仅 User 0（单用户） |
| `pm suspend/unsuspend` | 可用；重启后 `suspended=true` 保持 |
| `pm disable-user`（系统 App） | SecurityException: Cannot disable system packages |
| `am set-inactive / set-standby-bucket` | rc=0 但 `get-inactive`/bucket 不变（MIUI 忽略） |
| `cmd appops set ...` | ✅ 可用（`RUN_ANY_IN_BACKGROUND: ignore`）；**重启后恢复 allow** |
| `cmd appops ... BOOT_COMPLETED` | ❌ 非有效 op（`Unknown operation string`）；`WAKE_LOCK` 有效 |
| `device_config list` | 可读 activity_manager/device_idle/wifi 等命名空间 |
| `cmd overlay list` | 可读 RRO 覆盖（MIUI 的 overlays 可见） |
| `wm density 420` → `wm density 440` | ✅ 可写并恢复（成功的 "深度" 写操作） |
| `cmd package compile -m speed -f com.termux` | ✅ 成功（dex 编译优化） |
| `service list` / `settings list` | 可读；`settings` 的 `verifier_verify_adb_installs=0` 等可写 |

## 4. 技能卡

### 4.1 MIUI 下安装任意 APK（UI 自动确认）

1. 唤醒屏幕，`settings put system screen_off_timeout 1800000`；
2. 后台执行 `adb install -r -t -g app.apk`；
3. 循环 `uiautomator dump`，找 `clickable=true` 且文案为 `继续安装/安装/允许/确定` 的按钮，`input tap`；
4. 安装成功后恢复 `screen_off_timeout 15000`。
> 脚本：`scripts/adb/miui-adb-install.ps1`（已用于 Shizuku 安装成功）。

### 4.2 Shizuku 管理

```powershell
powershell -File scripts\adb\shizuku-adb-start.ps1 -Status
powershell -File scripts\adb\shizuku-adb-start.ps1 -Start     # 动态解析 libshizuku.so 路径
powershell -File scripts\adb\shizuku-adb-start.ps1 -Install   # 调 MIUI UI 自动安装
```
- 电池白名单：`cmd deviceidle whitelist +moe.shizuku.privileged.api`；后台：`cmd appops set ... RUN_ANY_IN_BACKGROUND allow`。
- **每次重启后重新 -Start**（adb 启动方式无法自启动，除非 root）。

### 4.3 proot 自建 ADB（手机服务器控制自身）
- 见 §3.3；脚本可扩展 `scripts/server/self-adb-setup.sh`（后续补）。
- 注意：共享 PC adbkey 等于把 PC 的 ADB 授权复制到手机内；仅限本机专用。

### 4.4 AppOps / 冻结 / 禁用的能力边界（选型表）

| 手段 | 会停止进程？ | 阻止后台/自启？ | 重启持久？ | MIUI 限制 | 可逆 |
|---|---|---|---|---|---|
| `cmd appops set RUN_ANY_IN_BACKGROUND ignore` | 需配合 force-stop | 部分（MIUI 可绕过） | ❌ 重置 | 中 | ✅ |
| `cmd package suspend` | 否（只限制交互/启动） | 部分 | ✅ | 低 | `unsuspend` |
| `pm disable-user`（系统包） | 是 | 是 | ✅ | ❌ 拒绝 | `enable` |
| `pm uninstall --user 0` | 是 | 是 | ✅ | 可（但**危险**） | `install-existing` |
| 设备所有者（Dhizuku/Hail/Island） | 是 | 是 | 是 | 需 provision，移除成本高 | **高风险** |

> 结论：无 Root 下 **suspend + appops + force-stop 是相对安全的组合**；不要用 uninstall 系统包（已有 bootloop 案例）。

### 4.5 项目选型建议（本机）
- **想去预装**：先用 UAD-NG 清单做只读比对 → 用 Canta(Shizuku) 仅处理"确认无用且非关键"的数据安装 App；系统包禁止 uninstall。
- **想冻结**：Hail + Shizuku（支持 suspend/force-stop/卸载重装），或 `pm suspend` + `am force-stop` 脚本。
- **想细粒度 AppOps/权限/网络策略**：AppManager（ADB/Shizuku 模式）。
- **想工作资料隔离**：Island（需 DPC provision，建议先在备用机验证）。
- **想要手机内 shell**：proot 自建 ADB（已验证）优于 LADB（后者需 GUI 配对且与 Shizuku 冲突）。

## 5. 风险与红线

| 风险 | 说明 | 处置 |
|---|---|---|
| 系统包 uninstall（最高危） | 导致 system_server crash/bootloop（本机曾发生） | 禁止；只允许 suspend/disable（MIUI 允许范围内） |
| Device Owner / Dhizuku | 移除可能需要恢复出厂；MIUI 兼容性不确定 | 不在主力机测试 |
| MIUI 安装弹窗自动化 | 依赖中文文案/分辨率；误点风险 | 已限定按钮白名单 + 安装前后台任务 |
| `adb tcpip 5555` | LAN 暴露 adbd；PC adbkey 复制到手机 | 仅在可信局域网使用；结束后 `adb usb`；更换密钥 |
| Shizuku（adb）权限 | 仅 shell 权限，不是 root（不能改 sysfs/刷机） | 明确能力边界；不要期望调频/zram |
| AppOps 重启重置 | MIUI 会恢复 allow | 需要时重放脚本（`perf-adb-apply.ps1`） |
| Shizuku 重启失效 | 无 Root 无法开机自启 | PC 端/开机后执行 `shizuku-adb-start.ps1 -Start` |

## 11. AppManager ADB 特权模式：验证成功（2026-11-10 18:45–18:55）

### 11.1 原理

AppManager 自带 `librun_server.so`，不依赖 Shizuku/root：只要用 ADB shell 执行 App 给出的"自定义命令"，就会以 **shell (UID 2000)** 身份启动本地特权服务端，App 再通过"网络调试（ADB）"模式连接。

### 11.2 实测步骤

1. AppManager → 设置 → 操作模式 → 「自定义命令」中复制命令（示例）：
   ```bash
   /data/app/~~.../io.github.muntashirakon.AppManager-.../lib/arm64/librun_server.so 60001 jolly-fit-dove am.jar main.jar io.github.muntashirakon.AppManager 0 0
   ```
2. PC/服务器侧执行：
   ```bash
   adb shell '<上面的命令>'
   # 输出：
   # Starting am_local_server as 2000:2000...
   # Local server has started.
   # Local server started successfully (PID: 32177).
   ```
3. AppManager：操作模式 → **更改模式 → 网络调试 → 应用**
   → 状态变为：
   ```
   ADB
   远程服务器启用中
   远程服务启用中
   已通过remote service连接
   ```
4. `netstat` 确认：`[::]:60001 LISTEN` + `127.0.0.1:60001 ESTABLISHED`（App 已连上）。

### 11.3 结论与注意

- ✅ **完全无 Root、无 Shizuku** 的 AppManager 特权模式可行，权限等同于 ADB shell。
- ⚠️ 端口 **60001 监听所有接口**（LAN 可访问，带 token 认证）；验证后已 `kill` 服务端以降低暴露面。
- ⚠️ 重启后服务端不会自动启动；需要重新执行命令（可作为 `after-reboot-android.ps1` 的扩展步骤）。
- AppManager 当前操作模式已切到「网络调试」，服务端未运行时显示"远程服务器未启用"。

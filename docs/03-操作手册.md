# 03 · 操作手册

> 本手册覆盖从**当前状态（未解锁/未 Root）**到"可用 Linux 服务器"的全部关键操作，按阶段组织。
> 每步都标注：**是否需要 Root / 是否会清数据 / 风险**。动手前先读 [04-风险与回滚](04-风险与回滚.md)。
> 标注 ⚠️ 的条目表示"方案可行但存在争议/需实测确认"，结论以 [02-可行性分析](02-可行性分析.md) 为准。

## 1. 阶段 A：免解锁先跑起来（Termux + proot）

> **不需要解锁、不需要 Root、不会清数据**。先验证"手机能不能当服务器用"，再决定是否冒险解锁。

### 1.1 Termux 基础配置

```bash
# Termux 内执行
pkg update && pkg upgrade -y
pkg install -y openssh termux-services proot-distro git rsync htop
termux-setup-storage        # 授权访问 /sdcard
```

> ⚠️ Termux 请用 **F-Droid / GitHub** 版本；Google Play 版本已停更（2020 年起），功能受限。

### 1.2 开启 SSH（Termux 内置 sshd，端口 8022）

```bash
# 生成密钥（在电脑上执行，然后把公钥传到手机）
ssh-keygen -t ed25519 -f $env:USERPROFILE\.ssh\id_haydn -C "haydn-server"

# 手机端：写入授权公钥
mkdir -p ~/.ssh && chmod 700 ~/.ssh
cat > ~/.ssh/authorized_keys << 'EOF'
# 粘贴 id_haydn.pub 的内容
EOF
chmod 600 ~/.ssh/authorized_keys

sshd    # 启动
# 查看是否监听
netstat -tlnp 2>/dev/null | grep 8022
```

```powershell
# 电脑端连接
ssh -p 8022 -i $env:USERPROFILE\.ssh\id_haydn 192.168.10.143
```

**保活（关键，HyperOS 会杀后台）**：
```bash
termux-wake-lock                     # 持有唤醒锁
# 然后到「设置 → 应用 → Termux → 省电策略」改为「无限制」
# 并允许「自启动」
```

**开机自启（Termux:Boot 已装）**：
```bash
mkdir -p ~/.termux/boot
cat > ~/.termux/boot/start-sshd.sh << 'EOF'
#!/data/data/com.termux/files/usr/bin/sh
termux-wake-lock
sshd
EOF
chmod +x ~/.termux/boot/start-sshd.sh
```

### 1.3 安装 Debian/Ubuntu（proot-distro）

```bash
proot-distro install debian          # 或 ubuntu / alpine
proot-distro login debian            # 进入 Linux 环境
```

容器内（Debian）：
```bash
apt update && apt install -y curl nginx htop
# 国内加速：替换源为清华/中科大镜像
sed -i 's/deb.debian.org/mirrors.ustc.edu.cn/g' /etc/apt/sources.list
```

> proot 是"用户态模拟 chroot"，**没有真正的内核隔离**；`systemd` 通常无法作为 PID 1 运行 ⚠️，服务建议用 `supervisord`、`s6` 或直接 `nohup` 启动。详见 [02-可行性分析](02-可行性分析.md)。

### 1.4 阶段 A 验收

- [ ] 手机重启后 Termux 自动运行、sshd 自动监听
- [ ] 电脑可免密 SSH 登录，断网重连可恢复
- [ ] proot Debian 内能 `apt install` 并跑起 nginx/一个示例服务
- [ ] 连续 24 小时不断线（记录 T1 快照，对比 T0 see docs/01）

> 阶段 A 已满足"轻量服务器"需求（SSH/定时任务/静态网站/内网服务）的话，可以**不解锁**，直接把阶段 B/C 视为可选。

## 2. 阶段 B：解锁 Bootloader（高风险，清数据）

> **前置**：已完成备份、确认接受失去保修与数据清空、了解解锁政策（见 [02-可行性分析](02-可行性分析.md)）。
> **会清空全部数据**，不可逆。

### 2.1 绑定账号并申请解锁资格（手机端）

1. 登录小米账号（设置 → 小米账号）；
2. 插入 SIM 卡并联网（部分政策要求）；
3. 开发者选项 → 「设备解锁状态」→ 绑定账号与设备；
4. 按提示等待资格期（近年政策通常要求账号绑定 **7 天/168 小时**，并可能要求社区等级/答题，以官方最新页面为准 ⚠️）；
5. 期间**不要**退出账号、不要刷机。

### 2.2 PC 端执行解锁

1. 官网下载「小米解锁工具（Mi Unlock）」并登录**同一账号**；
2. 手机进入 fastboot：关机 → 长按「音量下 + 电源」；
3. 数据线连接电脑，工具识别设备；
4. 点击「解锁」→ 手机确认 → 自动重启并抹除数据；
5. 解锁后重新开启开发者选项 + USB 调试。

```powershell
# 确认 fastboot 能看到设备
tools\platform-tools\fastboot.exe devices
# 查看解锁状态（解锁后 flash.locked 应为 0）
powershell -ExecutionPolicy Bypass -File scripts\adb.ps1 shell getprop ro.boot.flash.locked
```

### 2.3 解锁后的现实影响

- Play Integrity / 部分银行与支付 App 可能失效（可用 Magisk 隐藏等方案部分缓解 ⚠️）；
- 系统 OTA 升级可能提示"设备已解锁"，需手动处理；
- **保修通常失效**；
- 每次升级/刷机都要小心保持可用性。

## 3. 阶段 C：Root（按 02 结论选择 Magisk / KernelSU）

> 本机内核为 **5.4 QGKI（GKI 1.x 代）**。KernelSU 官方主要支持 GKI 2.0（5.10+），5.4 平台通常需要自编译内核 ⚠️；因此 **默认推荐 Magisk**，除非 02 给出更高确定性的做法。

### 3.1 Magisk（推荐路线）

> **本机分区形态（实测 2026-11-10）**：**A/B 双分区 + 动态分区**（`boot_a/boot_b`、`vendor_boot_a/b`、`dtbo_a/b`、`vbmeta_a/b`、`vbmeta_system_a/b`、`super`），**无 `init_boot`**。
> 因此：① 先备份原厂 `boot_a` / `boot_b`（或直接用官方固件包里的 `boot.img`）；② Magisk 修补 `boot.img`；③ `fastboot flash boot` 默认写**当前 slot**，如需显式指定用 `fastboot flash boot_a` / `boot_b`（**别写错 slot**，用 `fastboot getvar current-slot` 确认）。

```text
1. 下载与当前固件匹配的官方 fastboot 完整包（含 boot.img）
   - 机型 haydn / M2012K11C，当前版本 V816.0.15.0.UKKCNXM
   - 解包得到 images/boot.img
2. 手机安装 Magisk App（官方 GitHub Release）
3. 把 boot.img 传到手机 → Magisk App「安装 → 选择并修补一个文件」→ 生成 magisk_patched-*.img
4. 传回电脑
5. fastboot flash boot magisk_patched-*.img
6. fastboot reboot
7. 打开 Magisk App 确认版本与 Root 状态
```

```powershell
tools\platform-tools\fastboot.exe flash boot magisk_patched-xxxxx.img
tools\platform-tools\fastboot.exe reboot
```

> 若出现 bootloop 或卡米：`fastboot flash boot boot-stock.img` 回滚（原厂 boot 务必先备份）。
> 若提示 dm-verity/vbmeta 问题，可能需要 `fastboot --disable-verity --disable-verification flash vbmeta vbmeta.img` ⚠️（操作前确认机型教程）。

### 3.2 验证 Root

```powershell
powershell -ExecutionPolicy Bypass -File scripts\adb.ps1 shell su -c id
# 期望输出 uid=0(root)
```

### 3.3 Root 后立刻做的事

1. 备份原厂 `boot.img` 到 `backup/`（本项目已 gitignore 大文件，按需）；
2. 安装 Magisk 模块：`ACC`（充电控制）、`ZRAM`/`LADB` 按需；
3. 关闭系统自动更新（防止 OTA 破坏 Root）；
4. 再跑一次 `collect-device-info.ps1` 生成 T2 快照。

## 4. 阶段 D：服务器化进阶

### 4.1 用 chroot 替代 proot（需 Root）

```bash
# 以 Debian 根文件系统为例（放在 /data/local/linux/debian）
su -c "mkdir -p /data/local/linux"
su -c "mount -t tmpfs -o size=2G tmpfs /data/local/linux/dev  # 视需要"
su -c "chroot /data/local/linux/debian /bin/bash -c 'apt update'"
```
> chroot 有真正的文件系统隔离，但**共享 Android 内核**；服务管理同样没有 systemd，用 s6/runit/supervisord 管理。

### 4.2 容器可行性（P3 决策门）——本机已实测否决

> **2026-11-10 实测结论（详见 [02 §13](02-可行性分析.md)）**：
> 本机内核 `CONFIG_USER_NS` 与 `CONFIG_PID_NS` **未启用**（`/proc/self/ns` 只有 cgroup/mnt/net/uts），
> 因此 **Docker / Podman / containerd 均不可行**，root 也无法绕过（除非自编译内核 = C 路线，不推荐）。

如需自己复核，可在 Termux/手机上执行：

```bash
uname -a
zcat /proc/config.gz 2>/dev/null | grep -E 'CONFIG_(USER_NS|PID_NS|NET_NS|CGROUPS|OVERLAY_FS|SECCOMP)'
ls /proc/self/ns
unshare -U true
cat /proc/self/cgroup
```

**替代方案（路线 A/B1 内可用）**：

| 需求 | 可行替代 | 说明 |
|---|---|---|
| 想要"容器式"隔离 | `udocker`（用户态，基于 proot） | 🟡 无需 Root，但不是真容器；性能/兼容性有损 |
| 想要镜像/依赖打包 | proot-distro 多发行版 + supervisord | 🟡 够用，管理复杂度低 |
| 想要服务隔离与资源限制 | 不推荐强求；用独立用户 + cgroup（需 Root 且 cgroup 不完整） | ⚠️ 能力有限 |
| 真容器/真 Linux | 升级 B1（root + chroot）或放弃本机 | 见 [00-项目规划](00-项目规划.md) 的 Gate G-B |

> **纪律**：不要反复折腾 Android 内核开 USER_NS/PID_NS；那是 C 路线（自编译内核），风险与收益不成正比。

### 4.3 服务自启（Root 下）

Magisk 模块方式（`/data/adb/modules/<name>/service.sh`）：

```bash
#!/system/bin/sh
# 开机后等待系统稳定再拉起服务
sleep 20
/data/local/linux/bin/start-services.sh
```

Termux 方式见 1.2 的 `~/.termux/boot/`。

## 5. 优化调优清单（每项都可单独回滚）

> 原则：**一次只改一项**，改完观察 24h（温度/耗电/稳定性），记录到 `docs/01` 的变更表。

### 5.1 屏幕与显示（省电降温，效果最大）

```bash
adb shell settings put system screen_off_timeout 15000     # 15 秒熄屏
adb shell settings put global stay_on_while_plugged_in 0   # 插电也不长亮
adb shell svc power stayon false
adb shell settings put system screen_brightness 10         # 最低亮度
# 120Hz → 60Hz（不同版本设置项名不同，优先用系统设置 GUI）⚠️
adb shell settings put system peak_refresh_rate 60
```

### 5.2 动画与过渡（降低渲染开销）

```bash
adb shell settings put global window_animation_scale 0
adb shell settings put global transition_animation_scale 0
adb shell settings put global animator_duration_scale 0
```

### 5.3 网络

```text
首选：路由器里给手机 MAC 做 DHCP 地址保留（MAC 可在 设置→关于手机→状态信息 查看）
备选：系统设置里改为静态 IP（192.168.10.x / 24，网关 192.168.10.1，DNS 223.5.5.5）
```
```bash
adb shell settings put global private_dns_mode off   # 避免私有 DNS 干扰内网解析
adb shell settings put global wifi_sleep_policy 2    # 旧接口，部分版本无效 ⚠️
```

### 5.4 电池与充电（长期插电必做）

| 层次 | 做法 | 说明 |
|---|---|---|
| 系统 | 设置 → 电池 → 充电保护/智能充电 | HyperOS 有"智能充电保护"，夜间充到 80% ⚠️ 版本差异 |
| Root | Magisk 模块 **ACC**（Advanced Charging Controller） | 设置充电上限 60–80%，部分机型支持旁路供电 ⚠️ |
| 物理 | 通风摆放、远离热源、不覆盖 | 最有效且零成本 |
| 监控 | `dumpsys battery` 定时记录温度/健康 | 见 5.6 脚本 |

```bash
# 查看当前充电与温度
adb shell dumpsys battery | Select-String -Pattern 'level|status|health|temperature|AC powered'
```

> **不建议**直接拆电池直供（对安全与开机逻辑都有风险），除非有成熟教程与硬件改造经验。

### 5.5 CPU 与温控

```bash
# 查看
adb shell cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_governor
adb shell cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_available_governors
# 修改（需 Root）
adb shell su -c 'echo schedutil > /sys/devices/system/cpu/cpu0/cpufreq/scaling_governor'
adb shell su -c 'echo powersave > /sys/devices/system/cpu/cpu7/cpufreq/scaling_governor'  # 限制超大核
```

- 服务器场景建议 `schedutil`（默认）或降低超大核上限；**不要长期 `performance`**（120Hz+满载温控必崩）；
- 温度墙参考：CPU ≤ 70 °C、电池 ≤ 40 °C。

### 5.6 温度与健康监控脚本（Termux 内）

```bash
cat > ~/health.sh << 'EOF'
#!/data/data/com.termux/files/usr/bin/sh
CPU1=$(cat /sys/class/thermal/thermal_zone40/temp 2>/dev/null)   # cpu-1-0-usr
BAT=$(cat /sys/class/thermal/thermal_zone91/temp 2>/dev/null)    # battery
echo "$(date +%F\ %T) cpu1=${CPU1} bat=${BAT}"
EOF
chmod +x ~/health.sh
# 每 5 分钟记录
echo '*/5 * * * * ~/health.sh >> ~/health.log' | crontab -
```

> 热区索引以 `inventory/device-info-latest.json` 的 `hardware.thermalZones` 为准（不同固件可能变化）。

### 5.7 Debloat（免 Root 可逆）

```bash
# 禁用（可逆）示例：先列后禁
adb shell pm list packages -e | Select-String -Pattern 'miui.video|xiami.shop|miui.newhome'
adb shell pm disable-user --user 0 com.miui.video
adb shell pm disable-user --user 0 com.xiaomi.shop
adb shell pm disable-user --user 0 com.miui.analytics
# 恢复
adb shell pm enable com.miui.video
```

> 切勿批量 `uninstall` 系统包：可能破坏 HyperOS 服务联动。**只禁用明确不用的应用**，每批 3–5 个并观察。

### 5.8 日志与磁盘

```bash
# 限制容器/服务日志
# Docker: --log-opt max-size=10m --log-opt max-file=3
# proot: nohup 输出重定向到文件并 logrotate
df -h /data
```

## 7. 常见故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `adb devices` 显示 `unauthorized` | 手机未授权 | 手机端点「允许」并勾选"一律允许"；重插线 |
| `adb devices` 为空 | 数据线/驱动/USB 调试 | 换数据线；重装 MIUI USB 驱动；确认 USB 调试开 |
| `device offline` | adb server 状态异常 | `adb kill-server && adb start-server` |
| fastboot 看不到设备 | 驱动/线/模式 | 确认进了 fastboot（黑屏 + "FASTBOOT"）；装 Google USB Driver |
| SSH 连接被拒 | sshd 未运行/端口不同 | 手机 `sshd`；确认端口 8022；`pgrep sshd` |
| SSH 提示 host key 变更 | 手机重装后指纹变化 | `ssh-keygen -R '[192.168.10.143]:8022'` |
| Termux 进程被杀 | HyperOS 省电 | 电池策略改「无限制」+ `termux-wake-lock` |
| proot apt 很慢 | 源在国外 | 换 USTC/阿里源 |
| 充电慢/发热 | 高温保护/劣质充电器 | 换原装充电器；通风；温度降下来再充 |
| 卡米/bootloop | 刷机/OTA 失败 | `fastboot flash boot boot-stock.img`；MiFlash 刷全量包 |
| 无线 ADB 连不上 | 端口/IP 变化 | 重新配对（`adb pair`）；确认同一局域网 |

> **结论**：这是一台"干净、未解锁、未 Root、AVB 完整"的零售机。任何"把手机变成 Linux 服务器"的深度改造（原生 Linux、容器、系统级调优、内核参数）都必须先跨过 **解锁 Bootloader** 这道门；而解锁会**抹除全部用户数据**并失去保修。详见 [04-风险与回滚](04-风险与回滚.md)。

### 3.1 内核与容器能力实测（2026-11-10 补充）

> 只读探测，脚本 `scripts/probe-device.sh`（包装器 `scripts/probe-device.ps1`），原始输出 `inventory/capability-probe-latest.txt`。

| 检查项 | 实测结果 | 结论 |
|---|---|---|
| 内核版本 | `Linux 5.4.274-qgki-gcc3ec22f5061` | **GKI 1.x 代**（非 GKI 2.0） |
| `CONFIG_USER_NS` | `# CONFIG_USER_NS is not set` | rootless 容器不可行 |
| `CONFIG_PID_NS` | `# CONFIG_PID_NS is not set` | **容器运行时不可行（Docker/Podman 否决）** |
| `CONFIG_NAMESPACES` / `UTS_NS` / `NET_NS` | `=y` / `=y` / `=y` | 仅部分命名空间可用 |
| `/proc/self/ns` | 只有 `cgroup`、`mnt`、`net`、`uts` | 无 user/pid/ipc 命名空间 |
| `CONFIG_CGROUPS` / `CGROUP_BPF` / `CGROUP_DEVICE` | `=y` / `=y` / `not set` | cgroup 存在但不完整 |
| cgroup 形态 | 混合：v1 挂 `/dev/blkio`、`/dev/cpuctl`、`/dev/cpuset`、`/dev/memcg`；v2 挂 `/sys/fs/cgroup` 且 `cgroup.controllers` 为空 | **无 v2 委派 → systemd 不保证可用** |
| `OVERLAY_FS` / `BINFMT_MISC` / `SECCOMP_FILTER` | 均 `=y` | overlay / binfmt / seccomp 具备 |
| netfilter | `NF_NAT=y`、`NF_NAT_MASQUERADE=y`、`IP_NF_NAT=y`、`IP_NF_FILTER=y`、`BRIDGE=y`、`VETH=y`；`CONFIG_BRIDGE_NETFILTER` 未启用 | NAT 具备，桥接过滤缺失 |
| 运行时 `unshare` | `-U` → `Invalid argument`；`-m/-n/-p` → `Operation not permitted` | 用户态无法创建命名空间 |
| **分区形态** | **A/B 双分区**：`boot_a/b`、`vendor_boot_a/b`、`dtbo_a/b`、`vbmeta_a/b`、`vbmeta_system_a/b`；另有 `super`（动态分区）、`metadata`、`userdata`、`misc`、`persist`；**无 `init_boot`** | 刷机按 slot 操作；Magisk 修补 `boot.img` |
| 充电控制 sysfs | `/sys/class/power_supply/battery` 对 shell **Permission denied**（`charge_control_limit`/`charge_full`/`cycle_count` 均不可读） | 限充/旁路需 Root 后验证 |
| 温控服务 | ThermalHAL 2.0 已连接，Thermal Status 0（正常），cooling devices 含 `thermal-cpufreq-4/7`、`cpu-isolate*`、`cdsp` | 温控链路正常 |
| 电源状态 | 电池 100% FULL / 27 °C / GOOD；屏幕 `Dozing` | 空载基线正常 |

> **实测结论**：可以做**轻量 Linux 服务器**（Termux + proot，无需 root）；**不能做容器服务器**（内核缺 user/pid namespace，除非自编译内核）；服务管理用 **s6 / runit / supervisord** 而非 systemd；充电上限等硬件调优必须 Root 后确认 sysfs 节点。详见 [02-可行性分析 §13](02-可行性分析.md)。

## 4. SoC 与 CPU 拓扑

| 项目 | 值 |
|---|---|
| SoC | **Qualcomm Snapdragon 888（SM8350）**，`ro.soc.manufacturer = QTI` |
| 平台名 | `lahaina` |
| 指令集 | `arm64-v8a`（附带 `armeabi-v7a`、`armeabi`） |
| 核心数 | 8（1 + 3 + 4 三簇） |

| 调频策略 `policy` | 关联 CPU | 核心类型 | `scaling_max_freq`（实测） | `cpuinfo_max_freq`（硬件上限） | Governor |
|---|---|---|---|---|---|
| `policy0` | cpu0–3 | 4 × Cortex-A55 小核 | 1,804,800 Hz（1.80 GHz） | 1,804,800 Hz | `schedutil` |
| `policy4` | cpu4–6 | 3 × Cortex-A78 中核 | 2,342,400 Hz（2.34 GHz） | 2,419,200 Hz | `schedutil` |
| `policy7` | cpu7 | 1 × Cortex-X1 超大核 | 2,496,000 Hz（2.50 GHz） | 2,841,600 Hz | `schedutil` |

- 可用 governor：`conservative`、`powersave`、`performance`、`schedutil`（默认 `schedutil`）。
- 观察：超大核 X1 的 `scaling_max_freq` 被固件限制在 **2.50 GHz**（硬件上限 2.84 GHz），通常由温控/功耗策略动态约束 —— 服务器长期满载时，实际频率取决于热设计，不要指望跑满标称值。

## 12. 与"服务器化"直接相关的设备结论

1. **可作为服务器底座**：骁龙 888 + 8GB + 256GB，性能远超入门级 ARM 开发板，跑 SSH、Nginx、数据库、若干容器绰绰有余。
2. **改造前提明确**：未解锁 + 未 Root + AVB green，深度方案需先解锁；纯用户态方案（Termux + proot）可在**不解锁**的前提下先跑起来。
3. **内核是 5.4 QGKI**：GKI 1.x 代内核，对 KernelSU/容器/composefs 等现代方案的兼容性需要实测，不能想当然。
4. **没有有线网口、没有 MicroSD**：网络与存储扩展依赖 WiFi + USB-OTG。
5. **HyperOS 后台服务重（load 2.2+）**：空载负载就偏高，做服务器前必须做 debloat 与电源策略调优，否则功耗与温度浪费明显。
6. **电池是消耗品**：长期插电方案必须有充电上限/旁路，并接受"电池会在 1–2 年内衰减"的现实预期。

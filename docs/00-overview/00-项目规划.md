## 1. 项目愿景

> **把一台闲置的 Redmi K40 Pro 改造成"够用、安静、省电、可远程维护、风险可控"的家用 Linux 服务器**，承担 SSH 远程登录、文件同步/备份、轻量 Web 与自托管服务、下载/定时任务等用途；同时保留随时退回"普通手机"的能力。

### 1.1 项目目标（Goals）

| ID | 目标 | 判定标准 |
|---|---|---|
| **G1** | 可重复的设备基线与采集能力 | `scripts/adb/collect-device-info.ps1` 一条命令产出完整档案，[01 设备档案](../10-device/01-设备档案.md) 与实测一致 |
| **G2** | 不折腾、当天可用的服务器（A 路线） | Termux + proot 上线，SSH 免密可达、开机自启、断电恢复 |
| **G3** | 能力上限（B 路线，条件执行） | 解锁 + Root + chroot，服务能用 s6/supervisord 管理（Docker 已被实测否决） |
| **G4** | 优化与长期稳定 | 连续 30 天在线，无过热降频导致的服务中断；温度/功耗在阈值内 |
| **G5** | 运维闭环 | 监控告警 + 定期备份 + 远程重启兜底 + 故障手册 |

### 1.2 非目标（Non-Goals，明确不做）

- ❌ **不做日常主力机**：改造后不再依赖它打电话/拍照/移动支付（解锁后 Play Integrity 与部分金融 App 会失效）。
- ❌ **不追求"原生 Linux"**：haydn 没有可用的 postmarketOS/Nura、Ubuntu Touch、Droidian、Mobian 移植（见 [02 可行性分析](../10-device/02-可行性分析.md) §3），自己从零移植属于人月起的工作量。
- ❌ **不追求 Docker/K8s**：**本机内核 `CONFIG_USER_NS` 与 `CONFIG_PID_NS` 未启用（实测）**，容器运行时不可用（见 02 §13）。
- ❌ **不新增未受控公网端口**：公网仅经现有 frp 受控入口；默认局域网可用；ADB 不长期开启。
- ❌ **不刷第三方 ROM**（研究性质除外）。
- ❌ **不 Root、不解锁 BL**（B 路线已因 Gate B0 失败取消，见 §3.2 与 §10 ADR-006）。

### 1.3 硬约束（来自实测，不可协商）

| 约束 | 数值/事实 | 影响 |
|---|---|---|
| SoC | Snapdragon 888（SM8350），4×A55 + 3×A78 + 1×X1 | 性能足够，但**高负载发热与降频**是必须设计的部分 |
| 内存 | 8GB（MemTotal 7.13 GiB） | 跑 3–5 个轻量服务足够；数据库重负载不现实 |
| 存储 | 256GB UFS（可用约 193 GiB） | 充足；扩容只能 USB-OTG/NAS |
| 网络 | 仅 WiFi（无有线网口） | 必须做静态 IP/DHCP 保留 + 隧道兜底 |
| 内核 | 5.4.274-qgki（GKI 1.x 代） | USER_NS/PID_NS 未编译 → 容器否决；KernelSU 需自编译内核 |
| 分区 | **A/B 双分区 + 动态分区（super）** | 刷机需按 slot 操作（`boot_a`/`boot_b`），注意 Magisk 修补对应镜像 |
| 启动链 | Bootloader **锁定**，AVB green，dm-verity enforcing | 任何系统级改造必须先解锁 → 清数据 + 失保修 |
| 电池 | 4520 mAh，长期插电 | 必须在软件/物理两侧控制充电上限与温度 |
| 构建 | 仓库路径必须 ASCII | aapt2 不支持中文路径（原目录名已改名为 `haydn-server`） |

## 3. 技术路线决策

### 3.1 路线对比结论（详见 [02 可行性分析](../10-device/02-可行性分析.md)）

| 路线 | 结论 | 理由（含实测） |
|---|---|---|
| **A：Termux + proot-distro（不 root）** | ✅ **主路线（已落地）** | 零解锁、零丢数据、2–3 小时可上线；足够跑 SSH/Web/同步等轻量服务；缺点是假 root、无 systemd、无容器、I/O 有损耗 |
| **B1：解锁 + Root + chroot（s6/supervisord）** | ⛔ **已取消** | 能力上限更高，但 Gate B0 判定国行官方解锁不可用（2026-11-10），不再执行；执行手册归档至 [05 B 路线执行手册（已归档）](../90-archive/05-B路线执行手册.md) |
| **B2：Docker/Podman** | ❌ **否决** | 实测 `CONFIG_USER_NS is not set`、`CONFIG_PID_NS is not set`，`/proc/self/ns` 无 user/pid，运行时无法创建容器命名空间 |
| **C：自定义内核/第三方 ROM** | ❌ **不推荐** | 无公开 haydn 容器内核项目；编译/刷机风险极高、OTA 失效 |
| **D：原生 Linux（postmarketOS/Nura 等）** | ❌ **不可行** | 无 haydn 设备移植；同 SoC 兄弟机型（Mi 11/11 Ultra）仍标记 not booting |

### 3.2 决策门（Gate）

| Gate | 触发点 | 判定 | 不通过的处置 |
|---|---|---|---|
| **G-A** | P0 结束 | A 路线是否可立即开始？ | ✅ 通过：Termux/Boot 已装，设备可用 |
| **G-B0** | P4 开始前 | 国行（CN）机型能否通过官方渠道解锁？（2026 政策可能已关闭） | ❌ **失败（2026-11-10 用户确认小米社区 App 无解锁入口）→ B 路线终止，转 A+** |
| **G-B** | P2 结束（A 路线稳定运行 ≥ 7 天） | 是否值得升级到 B？ | ⛔ 不适用（B 路线已终止） |
| **G-C** | P1 开始前 | 用户是否已备份并确认"这台机可被清空"？ | ⛔ 不适用（不再进入 P4 解锁） |

> **最终策略**：A 主路线 + A+ 优化（无 Root）；**不为了"折腾"而解锁**。

## 8. 项目节奏与检查点

- **每次变更**：先在 [CHANGELOG](../../CHANGELOG.md) 记一条 → 变更 → 状态变化同步 [当前状态](当前状态.md)；
- **设备侧变更**：跑 `scripts/adb/collect-device-info.ps1` 生成 Tn 快照 → 对比 → 写入 [01 设备档案](../10-device/01-设备档案.md) 变更记录；
- **每周**：检查可用率、温度曲线、磁盘水位、备份是否成功；
- **每次版本升级/OTA**：禁止自动更新，手动评估后再动（见 [04 风险与回滚](../10-device/04-风险与回滚.md) R-08/R-13）；
- **文档**：`docs/` 与 `scripts/` 入 Git；`inventory/`、`tools/` 不入库（见 `.gitignore`）；文档改完跑 `python scripts/dev/check-links.py`。

## 1. 范围与术语

### 1.1 范围

**包含**：
- 服务器栈（Track A）：Termux + proot Ubuntu + supervisord + nginx + DSH + Console + 备份/审计。
- Android Bridge APK（Track B）：宿主状态采集、本地 HTTPS API、自启与常驻。
- 集成层（Track C）：`bridge_client.py`、Console/API、DSH 只读集成、server-ops。
- 部署、安全、可靠性、验收、回滚、开源许可。

**不包含**：
- 外部云服务/推送/异地备份/MFA（按用户要求暂不接入）。
- Root/KernelSU/Magisk、刷机、priv-app 系统应用。
- Bridge APK 的源码级实现细节（已实施，过程记录见 [33 Bridge MVP 实施记录](../50-bridge/33-Android-Bridge-MVP实施记录.md)；本文只定契约与验收）。
- 公网入口设计本身（frp 是可选外部组件，局域网可独立运行）。

### 1.2 术语

| 术语 | 含义 |
|---|---|
| Track A / 服务器栈 | proot Ubuntu 内的 Console/DSH/nginx/supervisord/备份等 |
| Track B / Bridge | Android 伴生 APK，采集宿主状态并提供 loopback HTTPS |
| Track C / 集成 | 服务器读取 Bridge、合并状态、Console/DSH 展示与治理 |
| DSH | 服务器上的 AI 控制面/运维入口，不是运行时必需依赖 |
| Bridge token | Bridge 与 server 之间的本地 API 凭据，**不得**暴露给 DSH 或公网 |
| Fallback | Bridge 不可用时回退 Termux 采集器/旧指标 |
| soak | 持续运行压测/观察窗口（本轮验收要求 24h） |

## 2. 目标与非目标

### 2.1 产品目标

| 编号 | 目标 |
|---|---|
| G1 | 手机服务器重启后，**无需 PC/ADB**，服务器 12 服务与 Bridge 均自动恢复 |
| G2 | Console/DSH 可获得**全部 App 可访问的实用手机状态**（电池/WiFi/内存/磁盘/热区/包/机型/屏幕/前台/网络累计等） |
| G3 | DSH 可自然语言查询状态、执行受控运维；**DSH 故障不影响 Bridge/服务器** |
| G4 | 本地 API 安全：loopback only、TLS、token/证书 pin、只读、限流、审计 |
| G5 | 所有关键链路可回滚；Bridge 失败可退回 Termux 采集器 |
| G6 | 文档/脚本/验收可复现，换机或重置后按 runbook 重建 |

### 2.2 非目标（明确不做）

- 不承诺"Android 全部系统级状态"：全局 `/proc/stat` 精确 CPU、`/proc/net/dev` 原始字节、`dumpsys`/`settings`/`appops`/冻结/停用等。
- 不把 Linux 服务器（proot/rootfs）塞进 Bridge APK。
- 不让 DSH 直接持有 Bridge token 或直接控制 Bridge 生命周期。
- 不做 system/priv-app、Device Owner、Root 方案（当前 BL 锁定）。
- 不引入外部云依赖作为运行前提。

## 3. 可行性结论与关键优化

### 3.1 方案选项矩阵

| 方案 | 自启 | 全部实用状态 | 特权 | PC 运行时依赖 | 结论 |
|---|---|---|---|---|---|
| 仅 proot 服务器 | 服务器可自启 | ❌ 电池/WiFi 等不可读 | ❌ | 无 | 不可行（沙箱） |
| Termux:API + 手动打开 | ❌ 需人工 | ✅ 部分 | ❌ | 重启后人工 | 仅作保底 |
| Shizuku（非 root） | ❌ 每次开机 ADB | ✅ | ✅ | 有 | 仅维护期可选 |
| **自建 Bridge APK** | ✅ BootReceiver+FGS | ✅ App 可访问 | ❌ | **仅首次 ADB** | **推荐（已落地）** |
| Bridge + 可选 Shizuku | ✅ Bridge；Shizuku 手动 | ✅ | ✅（Shizuku 运行时） | 仅 Shizuku 维护 | 后续可选 |
| Device Owner / Root | ✅ | ✅ | ✅ | 否 | 当前不可行（BL 锁） |

### 3.2 可行性结论

1. **Track A 已可行且已验证**：12/12 服务、自启、DSH、Console、备份均有实测基线（见 [当前状态](当前状态.md)）。
2. **Track B 技术可行且已落地**：Android 14/15 的 `BOOT_COMPLETED + specialUse Foreground Service` 是成熟路径；开源项目 HA Android / WallPanel 已验证同类模式。MVP（Phase 1）已完成，release 已安装运行。
3. **Track C 风险低且已接入**：server 侧 HTTP 客户端 + 字段合并 + DSH 文档约束，不改动服务器核心。
4. **最大不确定性**是 MIUI/HyperOS 的后台清理与用户授权（UsageStats/定位/通知）；必须用 **5 次重启 + 24h soak** 验收，并保留 fallback。**当前 5/5+1/1 重启已通过，24h soak 未完成**。

### 3.3 关键优化（相对原始理想）

| 原始想法 | 优化后 | 原因 |
|---|---|---|
| "全部功能" | **全部 App 可访问状态** + 明示不可得 | 无 Root 的硬边界；避免验收失败 |
| 深度集成 DSH | 深度**接口/治理**，不进程耦合 | DSH 300–400MB，故障隔离；DSH 无法启动 Android App |
| 把服务器放进 APK | 服务器保持 proot；Bridge 只做宿主桥 | 否则等于重做 Termux，工程/风险失控 |
| mTLS 一步到位 | MVP 用 **TLS + token + 证书 pin**；Phase 2 升 mTLS | 降低配对/证书复杂度，先可用再加固 |
| Push/WebSocket | **10s 轮询** 单端点 | 小数据量、实现简单、故障可观测 |
| 全量 sensors/UsageStats | MVP 只做电池/WiFi/Build/内存/磁盘/热区；Usage/Network Phase 2 | 权限授予多、收益后置，先保可用性 |
| Bridge 自带复杂 UI | 仅配对/设置页 | 减少攻击面与工作量 |
| Bridge 依赖 DSH | DSH 只读 Server API | 保护 token；DSH 故障不影响采集 |

### 3.4 构建前提（可行性硬条件）

> 现状（2026-11-11）：**构建链已就绪，Phase 0 完成**。细节以 [当前状态](当前状态.md) §6 为准，本节只列硬条件。

- **服务器**：按 [17 构建手册](../20-server/17-研究平台环境构建手册.md) 可重建；当前 12/12（见 [当前状态](当前状态.md)）。
- **Bridge**：
  - Android SDK **已安装**在仓库内 `tools/android-sdk`（`platforms;android-35` + `build-tools;35.0.0`）；JDK 17 已安装；
  - **无 Gradle、也不需要 Gradle**：用 `android-bridge/build.ps1`（aapt2 + javac + d8 + zipalign + apksigner）直接构建；
  - SDK 定位顺序：`$env:ANDROID_HOME` → `$env:ANDROID_SDK_ROOT` → 仓库 `tools/android-sdk`；JDK 定位顺序：`$env:JAVA_HOME` → 常见安装目录 → PATH 中的 javac；
  - **工程路径必须是 ASCII**：`aapt2` 在 Windows 上无法处理非 ASCII 路径（历史根因：原仓库目录名含中文导致 `Failed to stat ... android.jar`/assets 路径错误）。仓库已改名为 `haydn-server`，脚本对非 ASCII 路径直接报错提示，**不再使用 ASCII junction**；
  - 产物：`android-bridge/build/bridge.apk`（release 签名）+ `build/bridge.crt`，均 gitignored。
- 网络：无需 Gradle/Maven 在线依赖（无 Gradle 构建链）；APK 侧载安装（不走 Play）。
- 资源预算：Bridge 目标 RAM <30MB、空闲 CPU <1%（**目标值**，以实测验收）；DSH 约 300–400MB；手机 8GB 可容纳。
- 存储：APK + 证书/token 可忽略；不新增大型服务。

## 4. 总体架构

### 4.1 三轨拓扑

```text
┌──────────────────────────────┐
│ Track A: proot Ubuntu Server │
│ Console / DSH / nginx / ops  │
│ supervisord 12 services     │
│ 备份 / 审计 / 数据聚合        │
└───────────────┬──────────────┘
                │ Track C: bridge_client.py（loopback HTTPS + token/pin）
┌───────────────▼──────────────┐
│ Track B: Android Bridge APK  │
│ BootReceiver + specialUse FGS│
│ /v1/status（只读）            │
│ Collectors: battery/wifi/... │
│ Optional Shizuku client      │
└──────────────────────────────┘
```

### 4.2 设计原则（必须）

1. **单一聚合**：Server 是唯一聚合/存储/展示方；Bridge 只提供原始宿主状态。
2. **故障隔离**：Bridge、DSH、ADB 任一故障不得阻断其余组件。
3. **最小权限**：Bridge token/cert 只在 Server 本地使用；DSH 不持有。
4. **可回退**：Bridge 失败自动回退 Termux 采集文件；APK 可卸载/回滚。
5. **无 Root 边界**：不承诺特权数据；Shizuku/ADB 仅维护通道。
6. **许可干净**：不复制 GPL 项目代码；只用 Apache/BSD/MIT 作为库或参考。

### 4.3 组件边界

| 组件 | 职责 | 不负责 |
|---|---|---|
| Server | 聚合、存储、API、Console、DSH、备份、审计 | 不直接读取 Android 硬件 API |
| Bridge | Android 状态采集、本地 HTTPS、自启/常驻 | 不运行 Linux 服务、不做特权操作 |
| DSH | 自然语言查询/解释/受控 ops | 不持有 Bridge token、不控制 Bridge 生命周期 |
| ADB | 一次性装机/权限/白名单/维护 | 不是运行时依赖 |
| Shizuku | 可选特权数据源 | 不承诺自启；失败自动降级 |

---

### 4.4 设备无关性（OEM-agnostic）

- Bridge 包名/代码/数据契约**不得包含** `haydn`、`MIUI`、`xiaomi` 等设备/厂商假设；包名固定 `com.qingxuan.bridge`。
- 核心只使用标准 Android 权限/API；OEM 特有安装/自启/省电步骤只进入 **OEM profile**，不进入核心逻辑。
- Server 依赖 Termux/proot；OEM 仅影响 Termux:Boot/后台白名单，不改变 server 代码。
- 当前小米专属脚本/清单（如 MIUI 安装弹窗、debloat 清单）只作为**当前设备 profile**。
- OEM 适配矩阵、换机迁移、Root 选机见 [32 多厂商 Android 适配与迁移指南](../10-device/32-多厂商Android适配与迁移指南.md)。

## 5. 组件规范

### 5.1 Server（Track A）

**必须**：
- 12 个 supervisord 程序：api/fileui/frpc/gitea/nginx/runner/sshd/syncthing/webdav/dsh/dsh-login/dsh-guard。
- 启动链：Termux:Boot → `00-server.sh` → `ubuntu.sh` → `server-up` + `server-watch`。
- 对外：LAN 8080/8443、公网 frp（可选）、DSH `/app-login`；Bridge 仅 loopback。
- 备份：`server-backup` + `server-backup-sessions` 每日；`ops-audit` 审计。
- 配置：`server-ops` Tier1 只读、Tier2 受控写（确认/快照/审计）。

**应当**：
- `server-ops bridge status` 作为 Bridge 只读健康入口。
- Console `/api/sysinfo` 合并 bridge 数据并标注来源/新鲜度。

### 5.2 Bridge APK（Track B）

**必须**：
- 普通 App（非 system/priv-app），包名 `com.qingxuan.bridge`（不占用 Shizuku 保留名）。
- `BootReceiver`（BOOT_COMPLETED / MY_PACKAGE_REPLACED / QUICKBOOT_POWERON）+ `specialUse` FGS。
- `START_STICKY`；`onTaskRemoved` 使用 AlarmManager/JobScheduler 兜底；前台通知低优先级。
- 本地 HTTPS（loopback，默认 3099），仅 GET；token 认证 + 证书 pin；限流/body 上限。
- Collectors：Build、Battery、Wifi、Memory、Disk、Thermal、Packages（MVP）；Display、Usage、Network bytes、Uptime（Phase 2，**已接入**）。
- 权限最小化：INTERNET（仅 loopback）、ACCESS_WIFI_STATE、ACCESS_NETWORK_STATE、ACCESS_FINE_LOCATION（WiFi）、**NEARBY_WIFI_DEVICES（Android 13+，neverForLocation）**、RECEIVE_BOOT_COMPLETED、FOREGROUND_SERVICE(_SPECIAL_USE)、POST_NOTIFICATIONS、QUERY_ALL_PACKAGES。
- BootReceiver 应只监听系统 protected broadcast（BOOT_COMPLETED/MY_PACKAGE_REPLACED/QUICKBOOT_POWERON）；`exported=false` 仍可接收系统广播；若 `exported=true` 必须严格限制 intent-filter/permission。
- Android 13+ 应申请 POST_NOTIFICATIONS；即使通知被隐藏/被 OEM 重置为 ignore，FGS 仍运行，但必须在系统任务管理器可见。
- `debuggable=false`、`allowBackup=false`、组件最小导出、release 签名（**当前已达成**）。

**不得**：
- 提供 shell/exec/任意 URL/写设置端点。
- 绑定 `0.0.0.0` 或监听局域网/公网。
- 内嵌 Linux rootfs/服务器。
- 依赖 DSH 或 Termux:API 才能启动。

### 5.3 DSH（Track C）

**必须**：
- 只通过 Server API / `server-ops` 访问状态；不得直连 Bridge、不得读取 Bridge token。
- 遵循 `/root/AGENTS.md`：先 status/health；Tier2 需人工确认；Tier3 禁止。
- DSH 故障不影响 Server/Bridge；`dsh-guard` 负责自愈。

**应当**：
- 增加"手机状态/为什么卡"技能文案；使用 `/api/sysinfo` + `server-ops health`（当前以 AGENTS.md + `server-ops` 为最小集成）。
- 异常时解释"Bridge 不在线/回退 Termux"，不尝试 ADB 拉起。

### 5.4 ADB / Shizuku（维护面）

**必须**：
- ADB 仅用于首次装机、权限授予、白名单、诊断/优化；不作为运行时依赖。
- Shizuku 仅可选补充特权数据；不承诺非 root 自启（每次开机需 ADB）。
- 所有特权操作只允许人工 SSH/ADB，写入审计；DSH 不自动执行。

## 6. 接口规范

### 6.1 Bridge API v1（loopback HTTPS）

**端点（只读）**：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/v1/health` | 存活/版本；可无敏感数据，允许无 token（仅返回 ok/version） |
| GET | `/v1/version` | APK 版本/构建号 |
| GET | `/v1/status` | 完整状态快照（见 §7） |

**要求**：
- 仅 `127.0.0.1:3099`；TLS 1.2+；`Content-Type: application/json`。
- `Authorization: Bearer <token>`；token 存 Keystore/EncryptedSharedPreferences。
- Server 侧校验 **证书 SHA-256 pin**；证书轮换需 ADR/维护窗口。
- 10 req/s 限流；请求体 ≤ 16KB；只允许 GET；无 CORS（不需要）。
- 超时/错误：`{ok:false,error:"..."}`；不得泄露 token/路径。

### 6.2 Server API 扩展

`GET /api/sysinfo` 增加：

| 字段 | 含义 |
|---|---|
| `bridge_source` | `bridge` / `termux` / `none` |
| `bridge_age_s` | 最近成功数据年龄（秒） |
| `bridge_version` | APK 版本 |
| `bridge_last_seen` | ISO8601 |
| `bridge_available` | bool |
| `bridge_error` | 最近错误（可空） |
| `bridge_uptime_s` | Bridge 进程运行时长（Phase 2） |
| `display_interactive` / `display_locked` / `display_refresh_hz` / `display_brightness` | 屏幕状态（Phase 2） |
| `usage_foreground` / `usage_available` | 前台应用（Phase 2，需 Usage Access） |
| `net_rx_bytes` / `net_tx_bytes` / `network_since_boot` | 网络累计（Phase 2，TrafficStats） |
| `bridge_capabilities` | Bridge 能力清单（声明哪些字段可得） |

**必须**：Bridge 不可用/过期时返回 Termux 回退数据，并明确标注来源；不得把缺失字段伪造成 0；不可得字段一律 `null` 并可用 `bridge_capabilities` 解释。

### 6.3 Server-ops 扩展

`server-ops bridge status`（只读）输出：
- source/version/last_seen/age/缺失字段/最近错误；
- 不提供 Bridge 启停/重启（无法从 proot 控制 Android App）。

### 6.4 DSH 接口约定

- 数据：`GET /api/sysinfo`（只读）；
- 控制：`server-ops restart/start/stop/nginx/backup`（Tier2，`--confirm`）；
- **禁止**：DSH 调用 Bridge、读取 token、尝试启动 APK。

### 7.2 数据规则

- **单位**：MB（内存/swap）、GB（磁盘）、°C、mV、mA、Mbps、MHz、bytes。
- **null 语义**：不可得/无权限/厂商隐藏；不得用 0 替代。
- **新鲜度**：`bridge_age_s <= 30` 视为新鲜；>30s 标 stale；>120s 由 server 回退。
- **SSID**：Android 可能返回 `<unknown ssid>`；Bridge 应归一为 `null`，UI 显示"SSID 受系统限制"。
- **CPU**：普通 App 不保证全局精确；`approx_pct` 可空；不得伪造。
- **来源**：每个字段集带 source；Console/DSH 必须显示来源。
- **Phase 2 权限现实**：`GET_USAGE_STATS` 在 OEM 重启后可能回到 default（usage 字段为空，需再授权）；`POST_NOTIFICATIONS` 可能被重置为 ignore（FGS 仍工作）。缺失时按 null/能力清单展示，不阻塞主链路。

## 8. 安全规范

### 8.1 威胁模型

| 资产 | 威胁 | 控制 |
|---|---|---|
| Bridge token/cert | 同机恶意 App 读取/调用 | loopback + TLS + token + 证书 pin；Keystore；文件 600 |
| DSH 公网入口 | 爆破/越权 | Basic Auth + `/app-login` + 限流 429；Tier2 确认 |
| Server-ops | 误操作/提示注入 | AGENTS 策略、Tier1/Tier2、快照、审计 |
| 备份口令/保险库 | 泄露 | 加密备份；DSH 标记敏感；不进入聊天/日志 |
| ADB | 未授权调试 | 仅维护期启用；完成后关闭；记录 |

### 8.2 必须控制

- Bridge：**仅 loopback**；TLS；token；证书 pin；GET-only；限流；body 上限；无 shell 端点。
- Bridge：`debuggable=false`、`allowBackup=false`；release 签名；不导出 Service/Receiver（BootReceiver 仅接收系统广播）。
- Server：Bridge token 文件 `600`，仅 API 进程可读；DSH 不读；日志脱敏。
- DSH：不持有 Bridge token；不直接调用 Bridge；Tier2 必须人工确认；Tier3 禁止。
- 审计：server-ops 与 Console 操作留痕；Bridge 失败/回退记录。
- 证书/token 轮换：必须维护窗口；轮换前备份旧值；失败回滚。
- **禁止**：把 Basic 密码、DSH token、Bridge token、备份口令输出到聊天/日志/公网页面。

### 8.3 应当控制（Phase 2）

- mTLS（Server 客户端证书）；
- 配对码/二维码 + 一次性 token exchange；
- Android Keystore 硬件-backed key；
- 证书自动轮换与 pin 更新流程；
- 请求审计与异常速率告警。

> **当前状态**：Phase 2 字段（display/usage/network/uptime）已接入；以上 mTLS/配对/Keystore/证书轮换/速率告警**尚未落地**，属 Phase 2 剩余项。MVP 仍为"构建时自签 TLS + 静态 token + 证书 pin"（仅本机 MVP 可接受）。

## 9. 可靠性与自启规范

### 9.1 自启链路

| 组件 | 触发 | 机制 |
|---|---|---|
| 服务器 | Android BOOT_COMPLETED | Termux:Boot → `00-server.sh` → `ubuntu.sh` → `server-up` + `server-watch` |
| Bridge | Android BOOT_COMPLETED / MY_PACKAGE_REPLACED | BootReceiver → `startForegroundService` → specialUse FGS |
| DSH | supervisord autostart | `dsh` + `dsh-login` + `dsh-guard` |

**必须**：三链独立；任一链失败不得阻断其他链。

### 9.2 故障矩阵

| 故障 | 行为 | 恢复 |
|---|---|---|
| Bridge 崩溃/被杀 | Server 回退 Termux 数据并标 `bridge_source=termux`；Console 提示 | Bridge `START_STICKY` + Alarm/Job 自愈；MIUI 白名单 |
| DSH 崩溃 | Server/Console/Bridge 正常；DSH 不可用 | dsh-guard 自动重启 |
| Server 崩溃 | Bridge 仍运行；无聚合 | Termux:Boot/server-watch 恢复；重启验证 |
| Termux 被杀 | Bridge 仍运行；服务器不可用 | 需系统重启或手动 Termux；文档记录限制 |
| ADB 不可用 | 无影响 | 仅维护期需要 |
| Bridge 更新失败 | 回退旧 APK/停用 Bridge | APK 重装/降级；server 回退 |
| 证书/ token 失效 | Bridge 401；server 标记不可用 | 维护窗口轮换；回退 Termux |

### 9.3 SLO / 验收指标

| 指标 | 目标 |
|---|---|
| Server 服务 | 12/12 RUNNING，重启后 ≤120s 全就绪（当前基线 111s，2026-11-11） |
| DSH 登录 | `/app-login` 302；token 入口 200 |
| Bridge 可用率 | 24h ≥99%（server 轮询） |
| 数据新鲜度 | ≤30s（正常）；>120s 回退 |
| Bridge 资源 | RAM <30MB；空闲 CPU <1%（目标值，以实测为准） |
| 安全 | 仅 loopback；无未授权端点；无明文 token |
| 回滚 | APK/服务端回退 ≤10min |

> 当前验收进度：Phase 1 门禁通过（5/5 debug + 1/1 release 重启）；**24h soak 未完成**，Phase 4 全栈验收待办。

### 9.4 OEM/ROM 自启与白名单（MIUI 仅为当前示例）

**标准核心（所有 OEM 必须）**：
- `pm grant` 通知/定位；Usage Access 由用户 Settings 授权（如启用）。
- `cmd appops set <pkg> RUN_ANY_IN_BACKGROUND allow`。
- `dumpsys deviceidle whitelist +<pkg>`。
- 5 次重启验收；24h soak。

**OEM profile（人工/按机型）**：
- 小米/HyperOS：自启动、无限制省电、后台弹出；
- Samsung：后台使用限制"从不休眠的应用"；
- ColorOS/OxygenOS：允许后台活动、自启动；
- OriginOS/EMUI/MagicOS：自启动/后台耗电管理；
- 其他：按 ROM 实际设置。
- 完整矩阵见 [32 多厂商 Android 适配与迁移指南](../10-device/32-多厂商Android适配与迁移指南.md)。

> 当前实际：MIUI 自启动由 UI 人工放行后 5/5 重启通过；appops/deviceidle 单独不足。其他 OEM profile 与脚本化**待做**。

### 10.3 升级

- **Server**：Tier2 写操作 + 配置快照；DSH 升级按 [23 蓝绿升级演练](../30-dsh/23-DSH蓝绿升级演练.md) 蓝绿。

- Server：`config-snapshots` + `.bak-*`；`server-restore --verify`。

- 必须：server + sessions 每日备份；加密；`server-restore --verify` 抽检。
- 应当：Bridge APK/版本/token 配置纳入 ops 资产记录（不加密备份口令）。

## 12. 风险与 ADR

### 12.1 风险登记

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| OEM 杀 FGS（MIUI/HyperOS/ColorOS/OriginOS 等） | 中 | Bridge 不可用 | 标准 FGS+电池白名单+OEM profile+Job 兜底+回退 |
| Android 14/15 FGS 规则变化 | 中 | 启动失败 | specialUse；定期回归；targetSdk 评估 |
| SSID/权限受限 | 高 | WiFi 字段缺失 | 归一 null；显示"系统限制"；不追求 SSID |
| Usage/Network 权限被拒/重启重置 | 中 | 字段缺失 | 标 null + capabilities；不阻塞主链路；引导再授权 |
| 构建环境缺失 | 低（已解决） | 无法出 APK | SDK 已装 `tools/android-sdk`、JDK 17；`build.ps1` 自动探测 |
| **非 ASCII 路径导致 aapt2 失败** | 中（历史已踩） | 构建失败 | 仓库/工程路径保持 ASCII；脚本对非 ASCII 直接报错提示（**已通过改名解决**） |
| Bridge token 泄露 | 低 | 本机伪造状态 | loopback+TLS+pin；文件 600；轮换 |
| DSH 误操作 | 中 | 服务中断 | AGENTS、Tier2、确认、快照、审计 |
| 许可证污染 | 低 | 发布风险 | 不抄 GPL；用 Apache/BSD/MIT |

### 12.2 ADR（决策记录）

| ADR | 决策 | 理由 |
|---|---|---|
| ADR-001 | 自建 Bridge APK，不 fork Termux:API | receiver 不导出/无 boot/GPL；Bridge 可控 |
| ADR-002 | 服务器保持 proot，不嵌入 APK | 最小变更；否则重做 Termux |
| ADR-003 | BootReceiver + `specialUse` FGS，不用 dataSync | Android 15 禁止 BOOT 启动 dataSync；specialUse 适合监控桥 |
| ADR-004 | MVP 用 TLS + token + pin；Phase 2 mTLS | 降低实现/配对复杂度；先安全可用再加固 |
| ADR-005 | 状态用 10s 轮询，不用 WebSocket | 数据量小；简单可靠；可观测 |
| ADR-006 | DSH 深接口/浅耦合；不持有 token | 故障隔离/安全 |
| ADR-007 | Shizuku 仅可选维护，不作为自启依赖 | 非 root 每次开机需 ADB |
| ADR-008 | 保留 Termux 采集器回退 | 迁移期可用；Bridge 故障不丢数据 |
| ADR-009 | 不复制 GPL 代码；只用 Apache/BSD/MIT | 合规 |
| ADR-010 | 不做 system/priv-app/Device Owner | BL 锁/无 Root；普通 App 足够 |
| **ADR-011** | **仓库与文档结构重构（2026-11-11）**：仓库改名 `haydn-server`；docs 按主题分组（00-overview/10-device/20-server/30-dsh/40-console/50-bridge/90-archive/assets）；scripts 按运行侧分组（adb/termux/server/dev）；`build.ps1` 去 ASCII junction；状态集中于 [当前状态](当前状态.md)、变更集中于 [CHANGELOG](../../CHANGELOG.md) | aapt2 不支持中文路径（原目录名导致构建失败）；旧编号/裸路径引用混乱；降低新会话接手成本。评审与遗留见 [29 §8](29-项目文档评审报告.md) |

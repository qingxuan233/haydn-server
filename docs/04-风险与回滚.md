# 04 · 风险登记册与回滚方案

> 本项目动的是**启动链、系统分区、电池与网络暴露面**，属于"可能变砖 + 可能丢数据 + 可能有硬件损耗"的改造。
> 原则：**能回滚的才做，不能回滚的先想清楚再决定**；每个阶段开始前打快照（T0/T1…），结束后对比。

---

## 1. 风险分级标准

| 等级 | 概率 | 影响 | 处置策略 |
|---|---|---|---|
| 高 | 很可能发生 | 数据丢失 / 设备不可用 / 硬件损坏 | 必须设计缓解 + 回滚，未落实不进下一阶段 |
| 中 | 有可能 | 功能缺失 / 长时间停机 / 需要重刷 | 有缓解措施，接受剩余风险 |
| 低 | 罕见 | 体验下降 | 记录并观察 |

## 2. 风险登记册

| ID | 风险 | 触发信号 | 概率 | 影响 | 缓解措施 | 回滚 / 恢复 |
|---|---|---|---|---|---|---|

| **R-02** | 小米解锁资格不满足，或**国行（CN）机型 2026 年官方解锁通道已关闭**（本机实测区域 CN，风险显著升高） | 小米解锁工具提示资格不足 | 中 | 高 | 先做 Gate B0 解锁可行性验证（[05 §1](05-B路线执行手册.md)）；若国行受限则转 A+ 无 Root 优化 | 等待期继续用"免解锁"的 Termux 方案 |

| **R-06** | HyperOS 省电策略杀掉 Termux/sshd | SSH 断开、进程消失、开机不自启 | **高** | 中 | Termux 加入电池优化白名单、`termux-wake-lock`、前台服务、Termux:Boot 自启 | 手动重启服务；改用 Magisk 常驻服务（若已 Root） |

| **R-10** | 设备死机后无法远程恢复（单点故障） | SSH 无响应、手机失联数小时 | 中 | 中 | 智能插座远程断电重启、Magisk/脚本 watchdog 自动重启、UPS | 智能插座断电 10 秒上电；必要时现场处理 |

| **R-14** | 数据无备份导致业务配置丢失 | 容器/配置目录误删、存储故障 | 中 | **高** | 3-2-1 备份：手机本地 + PC/NAS + 异地；关键配置入 Git | 从备份恢复；不可恢复项提前识别 |

## 3. 关键风险详解

### R-01 解锁必然抹数据（最高优先级）

小米解锁会执行 `fastboot erase userdata`，**照片、聊天记录、应用数据全部清空**，且不可逆。因此：

1. 解锁前把手机当作"待迁移设备"处理：备份 → 迁移 → 确认无遗漏；
2. 微信/QQ 等聊天记录单独导出；
3. 解锁后再做一次系统初始设置，不要登录不必要的账号（减少后续风险面）。

### R-03 变砖与救援决策树

```
无法开机
├─ 能进 fastboot（音量下 + 电源）→ 有救
│   ├─ 只是 boot 镜像问题 → fastboot flash boot 原厂 boot.img
│   └─ 系统分区损坏 → MiFlash 刷官方完整包（fastboot 模式，需账号授权）
└─ 连 fastboot 都进不去 → 高风险
    ├─ 尝试长按电源 10–15 秒 / 音量上下 + 电源组合
    └─ 仍无反应 → EDL 模式（9008）需授权账号/售后，普通用户基本只能送修
```

> **本机补充（实测）**：A/B 双分区 + 动态分区（`boot_a/boot_b`、`super`）。刷机命令要对准**当前 slot**（`fastboot getvar current-slot`）；拿不准时用 `fastboot flash boot` 让 fastboot 选当前槽；刷前把两个槽的 boot 都备份（或保留官方固件包）。
>
> **纪律**：每次刷机前确认"原厂镜像已下载 + fastboot 可用 + 电量 > 50%"，三者缺一不可。

### R-04 电池与长期供电

手机做服务器 = 7×24 插电。锂电在 **满电 + 高温** 下老化最快。三个层次：

1. **软件层**：充电上限（如 60/70/80%）、旁路充电（部分机型支持）；
2. **物理层**：不要压在被子/密闭盒里，保持通风，避免阳光直射；
3. **接受层**：即使全部做到，1–2 年后容量衰减也很正常；把它当"可更换耗材"。

### R-07 容器可行性（P3 决策门）

Android 内核并非为通用容器设计，`Docker` 能跑起来需要同时满足：

- namespace（user/pid/mount/net/uts/ipc）
- cgroup（v1 或 v2 可写）
- overlayfs（或改用 vfs 存储驱动）
- iptables/nftables、`binfmt_misc`（跨架构可选）
- SELinux 策略允许

**验收方式**：跑 `docker info` + `docker run hello-world`，任一失败就记录原因并**退回 proot/chroot 路线**，不硬刚。

## 4. 回滚手册

### 4.1 服务变更回滚（最常用）

```bash
# 原则：先备份，再变更；配置集中管理，可用 Git
cp -a /data/.../config /data/.../config.bak-$(date +%F)
# 容器：保留旧镜像标签，回滚时重新 run 旧标签
# 包管理：apt 记录变更，必要时 apt install --reinstall
```

### 4.2 Root 回滚

- **Magisk**：Magisk App 内"卸载 Magisk → 完全卸载"并恢复原厂 boot；
- **KernelSU**：刷回原厂 `boot.img` 即可回到"解锁但未 Root"状态；
- 刷回命令（解锁状态下）：

```powershell
# 假设已解锁、已下载原厂 boot.img
tools\platform-tools\fastboot.exe flash boot boot-stock.img
tools\platform-tools\fastboot.exe reboot
```

### 4.3 恢复官方系统

1. 从小米官网下载**与机型/版本匹配**的完整固件包（`haydn` / `M2012K11C` / 国行 `UKKCNXM`）；
2. 用 `MiFlash` 在 fastboot 模式刷入（注意：部分版本需要账号授权）；
3. 刷回后 Bootloader 仍为解锁状态（需重新上锁才恢复 green，但**上锁有风险**，非必要不锁）。

### 4.4 紧急救援卡（打印/存手机外）

| 项目 | 内容 |
|---|---|
| 机型/代号 | M2012K11C / haydn / 国行 |
| 当前固件 | V816.0.15.0.UKKCNXM |
| 原厂镜像位置 | （待 P1 补充：`backup/firmware/`） |
| 解锁状态 | 未解锁（T0）→ 解锁后记录 |
| 救援命令 | `fastboot devices` → `fastboot flash boot boot-stock.img` |
| 关键备份 | `inventory/` 基线、`docs/01-设备档案.md`、服务配置 Git 仓库 |
| 远程带外 | 智能插座 IP/控制方式（待补充） |

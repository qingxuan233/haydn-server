# 09 · 性能优化方案与可行性分析（ADB 视角）

> 生成时间：2026-11-10 16:10（Asia/Shanghai）
> 范围：**只做分析与方案，不执行变更**（除一次无害的 `sm fstrim` 探针）。
> 目标：在**无 Root、仅 ADB + SSH** 的前提下，让这台手机的 Linux 服务器"更稳、更省、响应更快"。

---

## 1. 执行摘要

### 1.1 当前瓶颈排序（按实测影响）

| 排名 | 瓶颈 | 实测证据 | 影响 |
|---|---|---|---|
| **1** | **proot 自身 CPU 开销** | `dumpsys cpuinfo`：proot **33%**（27% kernel + 5.7% user） | 常驻税，所有 Linux 服务都绕不开 |
| **2** | **DSH 常驻 CPU** | node **9.5%**（2.5% user + 6.9% kernel）；日志显示有 **DevTools inspector 会话** | 可优化（关闭调试会话/调参） |
| **3** | 未使用系统应用占内存 | 搜狗输入法 275MB、Settings 264MB、phone 129MB、mms 117MB、milink 105MB、tsmclient 104MB、wallpaper 137MB | LMK 压力，影响 Termux 存活 |
| **4** | 看门狗/轮转的进程抖动 | `server-watch` 每 **45s** 跑 `metrics/drill/rotate/backup`；`server-rotate` 每轮启动 | 加剧 proot ptrace 开销 |
| **5** | 磁盘缓存与日志 | `/var/cache/apt` **337MB**、`/var/lib/apt/lists` 207MB；logcat 4×2MB | 占空间/内存，可清理 |

### 1.2 结论

- **ADB 无 Root 仍有一定优化空间**：主要来自「后台应用治理（standby/inactive/bucket）」「缓存/日志清理」「开关类设置」「一次性 TRIM」。
- **最大收益项不在 ADB 本身，而在服务器内部**：proot ptrace 开销 + 看门狗轮询 + DSH 调试会话，这三项合计可影响 **10–20 个百分点**的单核 CPU。
- **有若干"看起来能调"但实际需要 Root 的项**（CPU 调频、I/O 调度、zram/swap、温度墙、充电上限）——明确列为不可行，不浪费精力。

## 3. 可行性判定标准

| 判定 | 含义 |
|---|---|
| ✅ 可行（ADB） | 已探测命令存在且 shell 权限可用/高概率可用，可逆 |
| ⚠️ 有限 | 命令存在但权限/效果需实测；或有副作用需谨慎 |
| 🔒 需 Root | 无 Root 无法修改（明确不纳入方案） |
| ❌ 不可行/不建议 | 安全风险过高或系统禁止（如 MIUI canBeDisabled） |

## 4. 优化项清单与可行性

### A. Android 后台应用治理（ADB，无 Root）

| ID | 方案 | 命令/做法 | 预期收益 | 风险 | 可逆 | 判定 |
|---|---|---|---|---|---|---|
| A1 | 开启缓存应用冻结 | `settings put global cached_apps_freezer enabled` | 降低缓存进程内存 | 极低 | ✅ | ✅ 可行 |
| A2 | 增大空闲应用回收 | 对未使用系统应用 `am set-inactive <pkg> true` | 释放 200–400MB（搜狗/Settings/MMS/phone/tsm/milink 等） | 低（应用下次打开自动恢复 inactive=false） | `set-inactive false` | ⚠️ 权限待实测；高收益 |
| A3 | 限制后台桶 | `am set-standby-bucket <pkg> restricted`（对未使用应用） | 降低后台启动/唤醒 | 低-中（通知/后台可能延迟） | 设回 frequent/working_set | ⚠️ 可实测 |
| A4 | 后台限制级别 | `am set-bg-restriction-level <pkg> restricted_bucket/hibernation` | 更严格的后台限制 | 中（过度可能影响通知） | 设回 unrestricted | ⚠️ 可小范围试点 |
| A5 | 切换默认输入法 | `settings put secure default_input_method com.iflytek...` | 可能释放搜狗 ~100–270MB | 低（可切回；用户习惯） | 切回 | ⚠️ 需用户同意 |
| A6 | 一次性清理设置页残留 | `am force-stop com.android.settings` | 释放 264MB（临时） | 低（设置页关闭） | 打开设置即恢复 | ✅ 可行（一次性） |
| A7 | 清缓存/日志 | `logcat -c; logcat -G 1M` | 省 ~4–6MB 内存 | 极低 | 可再调大 | ✅ 可行 |
| A8 | 文件系统 TRIM | `sm fstrim`（每周/每月） | UFS 写入性能与寿命 | 极低 | 无 | ✅ 实测命令成功 |
| A9 | Termux 编译优化 | `cmd package compile -m speed -f com.termux` | Termux 启动/执行略快 | 低 | `cmd package compile --reset com.termux` | ✅ 命令存在 |
| A10 | 大应用强制停止（一次性） | `am force-stop com.android.mms / com.android.phone` 等 | 释放内存（会被系统重启） | 中（电话/短信功能暂停） | 自动恢复 | ⚠️ 不推荐常做 |

## 5. 推荐实施路线

### P0（低风险、可立即做，预计 30 分钟）

1. **C1** apt 缓存清理（释放 337MB）。
2. **A7** logcat 缓冲 8MB→4MB + 清空。
3. **A1** `cached_apps_freezer enabled`。
4. **A6** `am force-stop com.android.settings`（一次性，释放 264MB；注意先把设置页退出）。
5. **D1** 采样基线（关闭 DSH DevTools 后）。
6. **B4** 关闭 DSH DevTools 调试会话（解释 9.5% CPU 的主要来源）。

### P1（需 A/B 实测，预计 1–2 小时）

1. **C2+C3** 看门狗/日志轮转降频（45s→180s、rotate 每小时），对比 proot CPU 变化。
2. **A2+A3** 选 10–15 个"确定不用"的系统应用做 `set-inactive true` / `restricted` 试点，验证权限与效果（可逆）。
3. **A5** 切换默认输入法到讯飞（需你同意；可切回）。
4. **C4** DSH 内存上限/重启观察（若 DevTools 关闭后仍高）。
5. **D3** 服务延迟 A/B。

### P2（可选/需决策，预计 1 周观察）

1. **C5** Syncthing relays/global announce 关闭（仅当不需要公网同步）。
2. **A9** Termux dex 编译优化。
3. **A8** 周期性 `sm fstrim`。
4. 固定性能模式（**仅短时基准测试**，不建议常开：发热/降频风险）。
5. nginx 并发微调。

### 不做清单

- ❌ 继续卸载系统包 / 禁用非白名单系统组件（会再次 bootloop）
- ❌ `thermalservice override`、长期 `set-fixed-performance-mode`（安全风险）
- ❌ 改 CPU 调频/IO 调度/zram/swappiness（无 Root）
- ❌ 对 Termux 反复 kill-all / 强制停止（会杀服务）

## 7. 测量与验收方法（执行时必须做）

```bash
# 服务器侧：CPU 占比（Android 侧观察 proot/node）
adb shell dumpsys cpuinfo | head -12

# 内存/温度/负载
powershell -ExecutionPolicy Bypass -File scripts\phone-health.ps1

# 服务延迟（LAN/公网）
curl -s -o /dev/null -w "LAN: code=%{http_code} ttfb=%{time_starttransfer}s\n" http://192.168.10.143:8080/health
curl -s -o /dev/null -w "PUB: code=%{http_code} ttfb=%{time_starttransfer}s\n" https://47.97.70.99:44904/health

# A/B 要求：同一时段、无 DevTools 会话、屏息 10 分钟采样
```

**验收阈值（建议）**：

- proot CPU 平均 ≤ 25%（现状 33%）
- DSH idle CPU ≤ 4%（现状 9.5%，含 DevTools）
- MemAvailable ≥ 4.2 GiB（现状 3.97）
- 温度：CPU ≤ 45℃（空载）、电池 ≤ 35℃
- 服务 11/11 RUNNING、24h 无 watchdog 重启
- 公网/LAN `/health` 200、TTFB 无恶化

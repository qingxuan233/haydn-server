## 1. 项目愿景

> **把一台闲置的 Redmi K40 Pro 改造成"够用、安静、省电、可远程维护、风险可控"的家用 Linux 服务器**，承担 SSH 远程登录、文件同步/备份、轻量 Web 与自托管服务、下载/定时任务等用途；同时保留随时退回"普通手机"的能力。

### 1.1 项目目标（Goals）

| ID | 目标 | 判定标准 |
|---|---|---|
| **G1** | 可重复的设备基线与采集能力 | `scripts/collect-device-info.ps1` 一条命令产出完整档案，`docs/01` 与实测一致 |
| **G2** | 不折腾、当天可用的服务器（A 路线） | Termux + proot 上线，SSH 免密可达、开机自启、断电恢复 |
| **G3** | 能力上限（B 路线，条件执行） | 解锁 + Root + chroot，服务能用 s6/supervisord 管理（Docker 已被实测否决） |
| **G4** | 优化与长期稳定 | 连续 30 天在线，无过热降频导致的服务中断；温度/功耗在阈值内 |
| **G5** | 运维闭环 | 监控告警 + 定期备份 + 远程重启兜底 + 故障手册 |

### 1.2 非目标（Non-Goals，明确不做）

- ❌ **不做日常主力机**：改造后不再依赖它打电话/拍照/移动支付（解锁后 Play Integrity 与部分金融 App 会失效）。
- ❌ **不追求"原生 Linux"**：haydn 没有可用的 postmarketOS/Nura、Ubuntu Touch、Droidian、Mobian 移植（见 02 §3），自己从零移植属于人月起的工作量。
- ❌ **不追求 Docker/K8s**：**本机内核 `CONFIG_USER_NS` 与 `CONFIG_PID_NS` 未启用（实测）**，容器运行时不可用（见 02 §13）。
- ❌ **不暴露公网端口**：远程访问只走 Tailscale/WireGuard 内网隧道。
- ❌ **不刷第三方 ROM**（研究性质除外）。

### 1.3 硬约束（来自实测，不可协商）

| 约束 | 数值/事实 | 影响 |
|---|---|---|
| SoC | Snapdragon 888（SM8350），4×A55 + 3×A78 + 1×X1 | 性能足够，但**高负载发热与降频**是必须设计的部分 |
| 内存 | 8GB（MemTotal 7.13 GiB） | 跑 3–5 个轻量服务足够；数据库重负载不现实 |
| 存储 | 256GB UFS（可用约 193 GiB） | 充足；扩容只能 USB-OTG/NAS |
| 网络 | 仅 WiFi（无有线网口） | 必须做静态 IP/DHCP 保留 + 隧道兜底 |
| 内核 | 5.4.274-qgki（GKI 1.x 代） | USER_NS/PID_NS 未编译 → 容器否决；KernelSU 需自编译内核 |
| 分区 | **A/B 双分区 + 动态分区（super）** | 刷机需按 slot 操作（`boot_a`/`boot_b`），注意 Magisk 修补对应镜像 |
| 启动链 | Bootloader **锁定**，AVB green，dm-verity enforcing | 任何系统级改造必须先解锁 → 清数据 + 失保修 |
| 电池 | 4520 mAh，长期插电 | 必须在软件/物理两侧控制充电上限与温度 |

## 3. 技术路线决策

### 3.1 路线对比结论（详见 02）

| 路线 | 结论 | 理由（含实测） |
|---|---|---|
| **A：Termux + proot-distro（不 root）** | ✅ **主路线** | 零解锁、零丢数据、2–3 小时可上线；足够跑 SSH/Web/同步等轻量服务；缺点是假 root、无 systemd、无容器、I/O 有损耗 |
| **B1：解锁 + Root + chroot（s6/supervisord）** | ⚠️ **条件升级** | 能力上限更高（真 Linux 文件系统、可绑 22/80/443、无 ptrace 损耗、可用 iptables），代价是清数据 + 失保修 + 变砖风险 |
| **B2：Docker/Podman** | ❌ **否决** | 实测 `CONFIG_USER_NS is not set`、`CONFIG_PID_NS is not set`，`/proc/self/ns` 无 user/pid，运行时无法创建容器命名空间 |
| **C：自定义内核/第三方 ROM** | ❌ **不推荐** | 无公开 haydn 容器内核项目；编译/刷机风险极高、OTA 失效 |
| **D：原生 Linux（postmarketOS/Nura 等）** | ❌ **不可行** | 无 haydn 设备移植；同 SoC 兄弟机型（Mi 11/11 Ultra）仍标记 not booting |

### 3.2 决策门（Gate）

| Gate | 触发点 | 判定 | 不通过的处置 |
|---|---|---|---|
| **G-A** | P0 结束（现在） | A 路线是否可立即开始？ | ✅ 通过：Termux/Boot 已装，设备可用 |
| **G-B0** | P4 开始前 | 国行（CN）机型能否通过官方渠道解锁？（2026 政策可能已关闭） | ❌ **失败（2026-11-10 用户确认小米社区 App 无解锁入口）→ B 路线终止，转 A+** |
| **G-B** | P2 结束（A 路线稳定运行 ≥ 7 天） | 是否值得升级到 B？判据：① 需要 chroot/真 Linux 生态；② 接受清数据与保修损失；③ 解锁资格确认可行 | 保持 A 路线，不再升级 |
| **G-C** | P1 开始前 | 用户是否已备份并确认"这台机可被清空"？ | 未确认则禁止进入 P4（解锁） |

> **默认策略**：先走 A，用真实运行数据决定是否升级；**不为了"折腾"而解锁**。

## 7. 关键依赖与外部风险

| 类型 | 依赖 | 风险 |

| Q2 | 主要用途是什么？（文件同步/NAS、下载机、Web/自托管、监控、其他） | 决定服务清单与资源规划 | P2 前定 2–4 个核心用途，不求多 |
| Q3 | 是否愿意购置散热/智能插座/移动硬盘？ | 影响长期稳定性与扩展 | 建议：智能插座（远程重启）+ 小风扇（降温）优先 |
| Q4 | 家庭网络能否做 DHCP 地址保留/路由端口管理？ | 影响远程访问方案 | 建议：能则 Tailscale + 静态租约，不碰公网 |
| Q5 | 该手机是否有不可丢失数据/账号需要保留？ | 解锁会清空 | 解锁前必须迁移并验证 |
